1.什么是性能测试以及性能测试的价值和目的：

性能测试就是通过性能测试工具（Jmeter，loadRunner），通过特定方式，对系统施加一定的压力，正常、异常负载以及峰值来对系统实施压力，得到各项性能指标，保证系统的性能需求。

价值和目的：

1.评估系统的能力

2.识别系统的弱点（瓶颈）

3.检查系统隐藏的问题

4.检验系统的稳定性和可靠性

2.性能测试指标理解透彻以及测算

【虚拟用户数】：线程 = 用户  
【并发数】：指某一个时间，一定数量的虚拟用户**同时**对系统的某个功能进行交互。一般通过集合点实现。

【事务】：一个接口可以是事务，多个接口也可以是事务，一个流程可以是事务，事务代表一个完整的功能，由测试人员来决定。

【场景】：性能测试的用例，

【响应时间RT】：ResponseTime

1.平均响应时间： 一百次中的平均时间

2.中位数：排序后取中间值

基准测试：一个用户请求接口- 一般在200-500MS

压力测试： N个用户并发请求接口，2s左右即可（2 - 5 - 8 原则）

【TPS】：TPS（**Transactions Per Second**（每秒事务数））是系统重要的性能指标，用来衡量系统在一定时间内能够及处理的事务数量。 也就是吞吐量。

计算公式：总的事务数 / 总的运行时间

比如： 某一个系统一分钟能处理1000个事务，那么TPS = 1000 / 60 = 16.7

比如：按照去年的经营数据，2022年最高的一天由十万笔教育，预测2023年TPS需要多少合格？

总事务数量 = 10w, 时间 = 24*60*60 = 86400秒

那么TPC = 10w / 86400 = 1.157 = 1.2（估算）

1） 没有更详细的数据，根据二八定律（80%的事务在20%的时间完成）计算： TPC = 10w * 0.8 / 86400 * 0.2 = 8w / 17280 = 4.6 = 5(估算)

2) 如果有更详细的数据： 5万比交易是晚上 8 - 9 点完成的。

TPS = 50000 / 3600 = 13.9

业务的增长： 随着业务的增长还要上浮 30 %

TPS = 5w + 5w*0.3 / 3600 = 18

【QPS】（每秒查询量）：

**TPS、QPS（一般指的数据库更多一些）**、（前两个问的多）RPS、HPS（客户端每秒点击率）

【吞吐量】：

衡量网络成功传输的数据量，单位为Byte/s，每秒传输的字节数

【资源利用率】：

服务器：CPU， 内存， 磁盘。 网络
