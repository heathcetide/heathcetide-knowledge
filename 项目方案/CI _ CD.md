## 🚀 一、CI/CD 是什么？
| 缩写 | 全称 | 作用 |
| --- | --- | --- |
| CI | Continuous Integration（持续集成） | 代码频繁合并 + 自动构建 + 自动测试 |
| CD | Continuous Delivery（持续交付） | 自动发布到“可上线的环境”（但不自动上线） |
| CD | Continuous Deployment（持续部署） | 自动发布到生产环境（完全无人值守上线） |


一句话理解
CI 是为了代码质量，CD 是为了交付效率。

## 🛠️ 三、一个 CI/CD 流程案例（Spring Boot 项目）
**以 Git + Jenkins + Docker + K8s 为例**
1. ✅ **开发者提交代码**到 Git 分支（如 `dev`）
2. 🚀 **Jenkins 监听 Git 仓库变更**
3. 🔧 **Jenkins 自动构建流程**
 - 拉取代码
 - 运行测试（JUnit）
 - Maven 打包为 JAR
 - 构建 Docker 镜像（带版本号）
 - 推送到 Docker 镜像仓库（如 Harbor）
4. 🌐 Jenkins 通知部署环境（K8s、服务器）拉取最新镜像
5. 💡 部署完成后自动健康检查 + 回滚机制
6. 🔍 通知开发者部署结果

## 📌 简历上能写的方向（带亮点）
### ✅ **1. 设计并实现自动化部署流程**
描述你用 Jenkins 构建了完整的 CI/CD 流水线
+ 从 GitHub 自动拉取代码
+ 自动构建（Maven/Node/Nuxt/Docker）
+ 自动部署到测试或生产环境（如 PM2、Docker、K8s）
+ 失败自动通知（邮件/钉钉/企业微信）

这是真正的“工程能力 + DevOps 思维”。

---

### ✅ **2. 使用 Jenkinsfile 构建可维护流水线**
用 **Jenkins Pipeline**（声明式脚本）构建多阶段流程
```plain
groovy


复制编辑
pipeline {
 agent any
 stages {
 stage('Build') { steps { sh 'npm run build' } }
 stage('Test') { steps { sh 'npm test' } }
 stage('Deploy'){ steps { sh './deploy.sh' } }
 }
}
```

你可以说你构建了“可版本管理、模块化的自动化流水线脚本”，加分很多。

---

### ✅ **3. 环境隔离：使用 Docker 作为构建环境**
用 `docker` agent 在 Pipeline 中隔离构建环境（提高稳定性）

比如
```plain
groovy


复制编辑
agent {
 docker { image 'node:20-alpine' }
}
```

可以展示你熟悉容器化思想。

---

### ✅ **4. 集成测试 / 覆盖率报告 / 自动回滚**
如果你能做到
+ 自动跑单元测试（Jest / Pytest / JUnit）
+ 构建失败则不部署
+ 构建成功自动部署到服务器
+ 失败则回滚到上一个版本

那这个项目非常有**工程深度**，简历上能写成一段亮点经历。

## ✅ 建议你提升项目深度的方式

5. 日志归档 / 通知 / 多环境配置
6. 最好加点 **Docker 化部署**、甚至用 `docker-compose`
