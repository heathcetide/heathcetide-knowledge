在一个项目中，通常各层的测试目标和侧重点各不相同，以下是一些建议：

1. **Controller 层**
    - **目标**：验证接口（HTTP 请求/响应）是否正常，确保请求参数解析、数据校验、异常处理和响应格式正确。
    - **测试方法**：
        * 使用 `@WebMvcTest` 对 Controller 进行单独测试，只加载与控制器相关的 Bean。
        * 模拟 HTTP 请求（例如使用 MockMvc）来验证不同场景下的响应状态码和数据格式。
    - **注意事项**：通常不涉及业务逻辑细节，业务逻辑部分应该交由 Service 层处理。
2. **Service 层**
    - **目标**：测试核心业务逻辑，确保各个业务方法的实现符合预期。
    - **测试方法**：
        * 编写纯单元测试（JUnit、Mockito 等），可以对外部依赖（如 Repository 或 Mapper）进行模拟（Mock）或桩（Stub）处理。
        * 验证方法调用结果、异常情况和业务流程。
    - **注意事项**：尽量保持 Service 层测试的独立性，不依赖于具体的数据库实现或网络请求。
3. **Mapper/Repository 层**
    - **目标**：验证 SQL 映射、数据库查询以及数据持久化行为是否正确。
    - **测试方法**：
        * 使用集成测试（例如 `@DataJpaTest` 或 MyBatis 的测试配置）连接一个测试数据库（通常使用内存数据库如 H2）。
        * 验证 SQL 查询、更新操作是否返回预期结果。
    - **注意事项**：这些测试通常依赖于数据库环境，需要注意测试数据的准备和清理。

### 总结
+ **Controller 层**：测试 HTTP 接口、参数验证和响应格式，推荐使用 `@WebMvcTest` 和 MockMvc。
+ **Service 层**：测试业务逻辑，使用单元测试和 Mock 模拟外部依赖。
+ **Mapper/Repository 层**：测试数据层的 SQL 映射和数据库交互，使用集成测试和内存数据库验证查询与持久化结果。

各层测试互补，共同保障整个系统的质量。你可以根据项目复杂度和需求，合理分配测试精力，保证重点业务逻辑和数据操作都经过充分验证。
