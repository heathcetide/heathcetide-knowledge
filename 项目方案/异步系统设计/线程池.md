# 什么是线程池？
**线程池（Thread Pool）**，就是
**提前准备好一批线程，需要的时候拿来用，用完了再放回去，循环利用，而不是每次都新建线程。**

你可以把它想象成
+ 一个**线程的仓库**；
+ 里面有很多**现成的工人（线程）**；
+ 有活干时，叫一个工人出来干；
+ 干完活，工人**不辞退**，而是**回仓库休息，等待下次干活**。

---

# 为什么要有线程池？
如果**每来一个任务就 new 一个新线程**，问题就大了
+ **开销大**：创建和销毁线程需要时间、内存，频繁创建浪费资源；
+ **容易崩溃**：大量线程同时开，会把系统内存撑爆；
+ **管理混乱**：线程太多，操作系统调度也变慢。

**线程池的好处：**

| 好处 | 说明 |
| --- | --- |
| 节省资源 | 线程是重复利用的，避免频繁创建销毁 |
| 提升性能 | 有活就拿现成线程干，几乎不耗时 |
| 可控性好 | 可以设置最大线程数，防止服务器崩溃 |
| 更容易管理 | 统一调度线程，优化系统负载 |


---

# 程序中的线程池是啥样？
在 Java 里，线程池就是 `ExecutorService`。
比如常见的线程池创建方式
```plain
ExecutorService executor = Executors.newFixedThreadPool(10);
```

意思是
+ 创建一个**最多10个线程**的线程池；
+ 超过10个任务时，新任务会**排队等**。

---

# 线程池的主要参数（理解最重要！）
| 参数 | 说明 |
| --- | --- |
| 核心线程数 corePoolSize | 常驻的基本线程数，任务少也不销毁 |
| 最大线程数 maximumPoolSize | 最多能开多少线程 |
| 线程存活时间 keepAliveTime | 非核心线程空闲多久就销毁 |
| 队列容量 queueSize | 如果线程不够，用队列排队的容量 |
| 拒绝策略 | 队列满了以后怎么处理新任务（抛异常、丢弃、让调用方自己执行等） |


---

# 一个更清晰的流程图（文字版）
1. 有新任务来了；
2. 如果线程池里还有**空闲线程**，立刻执行；
3. 如果线程数还没到**核心数**，新建一个线程执行；
4. 如果核心数满了，**进任务队列排队**；
5. 如果队列也满了，**再看看能不能扩容到最大线程数**；
6. 如果最大线程数也满了，**执行拒绝策略**。

# 实战示例（Spring Boot 自定义线程池）
比如我们想自己控制异步用的线程池，创建一个配置类
```plain
@Configuration
@EnableAsync
public class AsyncConfig implements AsyncConfigurer {

 @Override
 public Executor getAsyncExecutor() {
 ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
 executor.setCorePoolSize(5); // 核心线程数
 executor.setMaxPoolSize(10); // 最大线程数
 executor.setQueueCapacity(50); // 任务队列大小
 executor.setKeepAliveSeconds(60); // 线程最大空闲时间
 executor.setThreadNamePrefix("AsyncTask-"); // 线程名前缀
 executor.initialize();
 return executor;
 }
}
```

这样你的 `@Async` 方法默认就用的是**自己配置的线程池**了！

# 线程池的拒绝策略（当线程池干不过来时怎么办？）
当线程池已经
+ 核心线程用完了，
+ 队列排满了，
+ 最大线程数也开到极限了， 这时候**再有新任务进来**，线程池就必须“做出选择”了。

这个选择，就是**拒绝策略（RejectedExecutionHandler）**。

---

## Java中自带的4种拒绝策略
| 拒绝策略 | 含义 | 适合场景 |
| --- | --- | --- |
| **AbortPolicy（默认）** | 直接抛异常 | 最安全，适合重要业务（比如订单处理） |
| **CallerRunsPolicy** | 谁提交谁自己跑任务（在当前线程执行） | 让系统自动降速，不丢任务（适合不追求极快） |
| **DiscardPolicy** | 直接丢掉任务，不通知 | 适合无关紧要的任务，比如日志收集失败也无所谓 |
| **DiscardOldestPolicy** | 丢掉队列中最早的一个任务，然后把新任务塞进去 | 适合实时性很高的任务（比如监控数据最新最重要） |


---

# 实战小结
| 你的情况 | 推荐拒绝策略 |
| --- | --- |
| 不能丢任务、不能乱来（比如支付、下单） | 用 `AbortPolicy` |
| 可以稍微慢点，但任务一定要执行 | 用 `CallerRunsPolicy` |
| 任务无关紧要，可以丢 | 用 `DiscardPolicy` |
| 保证最新的任务处理 | 用 `DiscardOldestPolicy` |


---

# 线程池最佳实践建议
| 建议 | 说明 |
| --- | --- |
| 核心线程数 = CPU核数 × 2 | I/O型任务可以再高一点，计算型任务要低一点 |
| 队列大小不要太大 | 否则内存爆了（一般是任务数的2~3倍） |
| 最大线程数设置合理 | 核心线程数 × 2 或 3，够用就行，防止线程太多反而卡死 |
| 合理设置keepAliveTime | 60秒够了，空闲线程及时回收 |
| 配拒绝策略 | 根据业务特性挑一个最适合的策略 |
| 打好监控 | 监控线程池活跃数、队列长度、拒绝次数，出问题能及时报警 |

# 一个示范版完美线程池配置
比如在Spring Boot里配一个专用的异步线程池
```plain
@Configuration
@EnableAsync
public class AsyncConfig implements AsyncConfigurer {

 @Override
 public Executor getAsyncExecutor() {

 executor.setQueueCapacity(100); // 队列100个
 executor.setKeepAliveSeconds(60); // 60秒
 executor.setThreadNamePrefix("AsyncTask-");
 executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy()); // 队列满了就自己跑
 executor.initialize();
 return executor;
 }
}
```

# **一、线程池怎么优雅关闭？**
## **为什么要优雅关闭？**
+ **程序停止时，如果线程池还在跑任务，****直接强停可能丢数据****！**
+ **比如处理订单、写日志、发消息，这些如果中断一半，后果很严重。**

**所以，****正确姿势是：**

**等线程池里的任务跑完，再安全退出。**

---

## **如何优雅关闭线程池？（标准流程）**
**标准代码示例：**

```plain
java


复制编辑
ExecutorService executor = Executors.newFixedThreadPool(10);

// 关闭
executor.shutdown();

// 等待所有任务完成，最多等30秒
try {
 if (!executor.awaitTermination(30, TimeUnit.SECONDS)) {
 executor.shutdownNow(); // 超时了，强制杀掉
 }
} catch (InterruptedException e) {
 executor.shutdownNow();
 Thread.currentThread().interrupt(); // 恢复中断状态
}
```

**解释：**

+ `**shutdown()**`**：不接新任务了，等已有任务跑完。**
+ `**awaitTermination()**`**：最多等一段时间，比如30秒。**
+ **如果超时还没结束，就 **`**shutdownNow()**`** 强行停掉。**

**注意****：一定记得 **`**Thread.currentThread().interrupt()**`**，恢复线程的中断标记，规范做法。**

---

## **Spring Boot里优雅关闭线程池**
**如果你是自己定义的 **`**ThreadPoolTaskExecutor**`**，可以直接在配置类里加上：**

```plain
java


复制编辑
executor.setWaitForTasksToCompleteOnShutdown(true);
executor.setAwaitTerminationSeconds(60);
```

**这表示：**

+ **关闭时，****等最多60秒****，让异步任务收尾；**
+ **超时后强制关。**

**示例：**

```plain
java


复制编辑
executor.setWaitForTasksToCompleteOnShutdown(true);
executor.setAwaitTerminationSeconds(60);
executor.initialize();
```

**这样，****Spring容器关闭时，会自动优雅关闭线程池****！**

# **二、线程池怎么监控？**
**线程池有很多****运行时指标****可以观察，最重要的有这些：**

| **指标** | **含义** |
| --- | --- |
| **getPoolSize()** | **当前线程池里线程总数** |
| **getActiveCount()** | **正在忙碌工作的线程数量** |
| **getQueue().size()** | **当前排队等待的任务数量** |
| **getTaskCount()** | **总共提交过多少个任务** |
| **getCompletedTaskCount()** | **已经完成了多少任务** |


---

## **示例：实时监控线程池状态**
```plain
java


复制编辑
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);

// 每5秒打印一次线程池状态
scheduler.scheduleAtFixedRate(() -> {
 ThreadPoolExecutor threadPoolExecutor = (ThreadPoolExecutor) executor;
 System.out.println("当前线程池大小：" + threadPoolExecutor.getPoolSize());
 System.out.println("活跃线程数：" + threadPoolExecutor.getActiveCount());
 System.out.println("排队任务数：" + threadPoolExecutor.getQueue().size());
 System.out.println("总提交任务数：" + threadPoolExecutor.getTaskCount());
 System.out.println("完成任务数：" + threadPoolExecutor.getCompletedTaskCount());
 System.out.println("-----");
}, 0, 5, TimeUnit.SECONDS);
```

**这样你可以****实时看到线程池运行情况****，防止出现：**

+ **线程数飙升**
+ **队列爆了**
+ **拒绝任务**

**监控是防止事故的第一道防线！**

# **高并发项目异步+线程池实战经验总结**
---

## **1. 线程池一定要自己配置，不用默认的！**
+ **默认线程池（Spring默认、Executors默认）不靠谱：**
 - **队列太大，容易内存爆。**
 - **核心线程数太少，处理不过来。**

**正确做法：**** 自己在 **`**@Configuration**`** 里配线程池，比如：**

```plain
java


复制编辑
@Bean(name = "asyncTaskExecutor")
public ThreadPoolTaskExecutor asyncTaskExecutor() {
 ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
 executor.setCorePoolSize(10);
 executor.setMaxPoolSize(20);
 executor.setQueueCapacity(1000);
 executor.setKeepAliveSeconds(60);
 executor.setThreadNamePrefix("Async-Task-");
 executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
 executor.initialize();
 return executor;
}
```

**关键点****：**

+ **核心线程数根据你的CPU和业务量来配；**
+ **队列大小别太大，1000够大了；**
+ **拒绝策略一般用 **`**CallerRunsPolicy**`**，防止任务丢了。**

---

## **2. 高并发场景一定要限流、限速！**
**高并发（比如秒杀、爬虫、大量API请求）时：**

**如果线程池进来的任务太多，不做限流 → 直接爆掉。**

**正确做法：**

+ **加令牌桶限流、漏斗限流；**
+ **前端或接口网关（如Nginx、API Gateway）限速；**
+ **后端可以用 Guava RateLimiter 速率控制：**

```plain
java


复制编辑
RateLimiter limiter = RateLimiter.create(100); // 每秒100个许可

if (limiter.tryAcquire()) {
 // 放行
} else {
 // 拒绝处理或排队
}
```

---

## **3. 任务要有超时控制！**
**很多异步任务****有可能永远跑不完****，比如卡住了，网挂了，第三方接口炸了。**

**正确做法：**

+ **给每个异步任务加超时限制；**
+ **比如用 **`**CompletableFuture**`** + **`**orTimeout()**`**：**

```plain
java


复制编辑
CompletableFuture.supplyAsync(() -> {
 // 你的任务
}).orTimeout(30, TimeUnit.SECONDS);
```

**30秒还没跑完，就自动取消！**

---

## **4. 拒绝策略选好，能自救！**
**实战总结：**

+ **AbortPolicy****：对重要核心业务（比如支付）；**
+ **CallerRunsPolicy****：对可以稍慢但不能丢的（比如导出Excel、批量处理）；**
+ **DiscardPolicy/DiscardOldestPolicy****：对可以丢的非核心业务（比如日志、监控采集）。**

---

## **5. 合理监控+报警**
**线程池用起来，一定要配监控，否则你根本不知道它啥时候出事。**

**监控什么？**

+ **线程池活跃线程数**
+ **队列长度**
+ **拒绝次数**
+ **最大线程数是否达到极限**

**Spring Boot里监控线程池可以这么搞：**** 用 **`**actuator**`** 结合自定义 **`**metrics**`**，实时打点到 Prometheus 或 Grafana。**

# **为什么要管理异步结果？**
**因为异步任务是“各自跑自己的”，结果很分散。****
****如果不管理好，就会出现：**

+ **有的任务出错了你不知道；**
+ **有的任务还没跑完你就以为结束了；**
+ **需要汇总所有异步结果时，根本拿不到。**

**所以——
****多个异步任务，必须有个“总指挥”统一管理。**

---

# **如何优雅管理异步任务？**
## **核心方法：用 **`**CompletableFuture**`
**Java里最牛逼的异步管理神器就是：**

```plain
java.util.concurrent.CompletableFuture
```

**它支持：**

+ **聚合多个异步任务**
+ **收集所有执行结果**
+ **捕获异常**
+ **设置超时**
+ **统一处理完成或失败的情况**

---

## **最常用的3种模式**
| **模式** | **说明** |
| --- | --- |
| `**allOf()**` | **等****所有任务****都完成** |
| `**anyOf()**` | **只要有一个****完成就继续** |
| **单独处理异常** | **用 **`**.exceptionally()**`<br/>** 或 **`**.handle()**`<br/>** 捕获单个任务异常** |


---

# **具体实战示范！**
**假设我们要并发抓取5个网页：**

```plain
java


复制编辑
List<String> urls = List.of(
 "http://example.com/1",
 "http://example.com/2",
 "http://example.com/3",
 "http://example.com/4",
 "http://example.com/5"
);

ExecutorService executor = Executors.newFixedThreadPool(5);

List<CompletableFuture<String>> futures = urls.stream()
 .map(url -> CompletableFuture.supplyAsync(() -> {
 // 模拟请求网页
 return "Fetched: " + url;
 }, executor).exceptionally(e -> {
 // 捕获异常，避免程序崩溃
 System.err.println("任务失败：" + e.getMessage());
 return null;
 }))
 .toList();

// 等所有任务完成
CompletableFuture<Void> all = CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]));

// 等待并收集结果
List<String> results = all.thenApply(v ->
 futures.stream()
 .map(CompletableFuture::join) // join()不会抛检查异常
 .toList()
).join();

// 打印结果
results.forEach(System.out::println);

executor.shutdown();
```

---

# **小结这段示范：**
+ **并行提交****：每个url是一个异步任务。**
+ **异常处理****：每个任务用 **`**.exceptionally()**`** 保底。**
+ **统一等待****：用 **`**allOf()**`** 等待所有任务完成。**
+ **统一收集****：用 **`**.join()**`** 收集各自的返回值。**

**做到真正的：跑得快、拿得稳、错了也不慌。**

---

# **高级玩法：超时+失败保护**
**如果担心有任务卡死，可以加超时保护，比如：**

```plain
java


复制编辑
CompletableFuture.supplyAsync(() -> {
 // 你的业务逻辑
}).orTimeout(5, TimeUnit.SECONDS)
 .exceptionally(e -> {
 System.err.println("超时或异常：" + e.getMessage());
 return "默认值";
 });
```

+ **超过5秒没完成 → 抛超时异常**
+ **用 **`**.exceptionally()**`** 捕获异常，返回默认值，****保证整体流程不崩**

# **什么是异步链式编排？**
**简单来说就是：**

**多个异步任务，有先后顺序，按依赖关系一环接一环执行。**

**不像普通的 **`**supplyAsync()**`** 都是一起跑，链式编排可以：**

+ **一个异步完成后，接着跑下一个异步；**
+ **异步之间传递数据；**
+ **中途异常了可以统一处理。**

**像流水线一样，一个一个来。**

---

# **核心API**
| **方法** | **作用** |
| --- | --- |
| `**thenApply()**` | **前一步成功后，处理结果，并返回新的值（同步方式）** |
| `**thenCompose()**` | **前一步成功后，返回****一个新的异步任务****（链式异步）** |
| `**thenAccept()**` | **前一步成功后，处理结果，不返回新的值** |
| `**thenRun()**` | **前一步成功后，执行一个无参数无返回值的动作** |
| `**exceptionally()**` | **异常时处理** |
| `**handle()**` | **成功或失败都处理** |


---

# **实战示范1：简单链式调用**
**比如我要先查用户资料，然后查用户订单数量，然后发送通知：**

```plain
java


复制编辑
CompletableFuture.supplyAsync(() -> {
 System.out.println("查询用户信息...");
 return "用户张三";
}).thenApply(user -> {
 System.out.println("查询订单数量...");
 return user + " 的订单数量：5个";
}).thenAccept(orderInfo -> {
 System.out.println("发送通知：" + orderInfo);
});
```

**执行结果：**

```plain
复制编辑
查询用户信息...
查询订单数量...
发送通知：用户张三 的订单数量：5个
```

**一环接一环！**

# **实战示范2：异步链（真正异步，不阻塞）**
**上面用的是 **`**thenApply()**`** ——同步处理。
****如果你想****每一步都异步****，用 **`**thenCompose()**`**！**

```plain
java


复制编辑
CompletableFuture.supplyAsync(() -> {
 System.out.println("拿到Token...");
 return "Token123";
}).thenCompose(token -> CompletableFuture.supplyAsync(() -> {
 System.out.println("用Token请求接口...");
 return "接口返回的数据";
})).thenAccept(result -> {
 System.out.println("处理返回的数据：" + result);
});
```

**每一步都是独立异步，线程池调度，更加高效！**

# **实战示范3：异常链式处理**
**如果中间某一步异常了，如何优雅处理？**

```plain
java


复制编辑
CompletableFuture.supplyAsync(() -> {
 throw new RuntimeException("服务崩了！");
}).thenApply(data -> {
 // 这里不会进来
 return data + "处理";
}).exceptionally(e -> {
 System.err.println("捕获到异常：" + e.getMessage());
 return "使用默认值补救";
}).thenAccept(finalResult -> {
 System.out.println("最终处理结果：" + finalResult);
});
```

**执行输出：**

```plain
makefile


复制编辑
捕获到异常：java.lang.RuntimeException: 服务崩了！
最终处理结果：使用默认值补救
```

**所以，链式编排一定要带上 **`**.exceptionally()**`** 或 **`**.handle()**`**，防止一崩全崩！**

# **总结一下链式编排套路**
| **需求** | **用法** |
| --- | --- |
| **上一步返回后做同步处理** | `**thenApply**` |
| **上一步返回后继续异步任务** | `**thenCompose**` |
| **处理结果但不需要返回** | `**thenAccept**` |
| **上一步完成就做动作，无需结果** | `**thenRun**` |
| **捕获异常并补救** | `**exceptionally**` |
| **成功失败都统一处理** | `**handle**` |

# **什么是异步任务组合？**
**一句话：**

**多个异步任务并发执行，等它们全部完成，再统一处理结果。**

**比如：**

+ **并发请求 订单系统、物流系统、会员系统 → 全部返回后统一组装数据返回前端。**
+ **并行计算各个子模块得分 → 汇总总分。**

---

# **核心API：**`**CompletableFuture.allOf()**`** 和 **`**CompletableFuture.anyOf()**`
| **方法** | **说明** |
| --- | --- |
| `**allOf()**` | **等待所有异步任务都完成** |
| `**anyOf()**` | **只要有一个完成就继续** |


---

# **实战演示1：等待所有任务完成（allOf）**
```plain
java


复制编辑
ExecutorService executor = Executors.newFixedThreadPool(5);

CompletableFuture<String> task1 = CompletableFuture.supplyAsync(() -> {
 sleep(1);
 return "结果A";
}, executor);

CompletableFuture<String> task2 = CompletableFuture.supplyAsync(() -> {
 sleep(2);
 return "结果B";
}, executor);

CompletableFuture<String> task3 = CompletableFuture.supplyAsync(() -> {
 sleep(3);
 return "结果C";
}, executor);

// 聚合
CompletableFuture<Void> all = CompletableFuture.allOf(task1, task2, task3);

// 等待所有完成后收集结果
List<String> results = all.thenApply(v -> {
 List<String> list = new ArrayList<>();
 list.add(task1.join());
 list.add(task2.join());
 list.add(task3.join());
 return list;
}).join();

// 打印
results.forEach(System.out::println);

executor.shutdown();
```

**执行顺序：**

+ **三个任务一起跑**
+ **最慢的task3跑完**
+ **收集所有结果**

---

# **小技巧：别直接用 **`**get()**`**，用 **`**join()**`
| **方法** | **说明** |
| --- | --- |
| `**get()**` | **会抛异常（需要 try-catch）** |
| `**join()**` | **遇到异常也转成RuntimeException，链式更舒服** |


**所以收结果用 **`**.join()**`**！**

# **如何监控****被拒绝的任务****？**
**自己加一个拒绝策略，记录每次被拒绝的次数！**

```plain
java


复制编辑
@Slf4j
public class MonitorAbortPolicy implements RejectedExecutionHandler {

 private AtomicLong rejectCount = new AtomicLong(0);

 @Override
 public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
 rejectCount.incrementAndGet();
 log.error("任务被拒绝了！活跃线程：{}, 队列长度：{}", executor.getActiveCount(), executor.getQueue().size());
 throw new RejectedExecutionException("任务被拒绝");
 }

 public long getRejectCount() {
 return rejectCount.get();
 }
}
```

```plain

```

**然后监控里加上：**


# **为什么异步任务必须加超时保护？**
**因为异步任务本质是****不可控的****，比如：**

+ **某个远程接口卡死了，**
+ **某个数据库查询很慢，**
+ **某个第三方系统掉线，**

**如果你不加超时保护，就会出现：**

+ **异步任务永远挂在那里，占线程不释放，**
+ **队列塞爆、线程池耗尽，最终整个系统崩溃！**

**所以必须做到：**

**在合理时间内异步任务必须完成，否则就强制超时退出。**

---

# **核心两种超时保护方式**
| **方式** | **适用场景** | **备注** |
| --- | --- | --- |
| **1. CompletableFuture自带的超时API** | **常规异步，简单快速** | **推荐优先用** |
| **2. 自己手动封装超时机制** | **特殊需求，复杂场景** | **可更灵活处理** |


---

# **方法一：CompletableFuture原生超时控制**
**直接用 **`**.orTimeout(timeout, unit)**`**！**

**比如：**

```plain
java


复制编辑
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
 sleep(5); // 假设5秒才能返回
 return "任务完成";
}).orTimeout(3, TimeUnit.SECONDS); // 规定最多3秒

future.whenComplete((result, ex) -> {
 if (ex != null) {
 System.out.println("超时或异常：" + ex.getMessage());
 } else {
 System.out.println("执行结果：" + result);
 }
});
```

+ **如果3秒内没完成，就抛 **`**TimeoutException**`**。**
+ **你可以在 **`**whenComplete()**`**里统一处理异常或者降级返回。**

**输出：**

```plain
makefile


复制编辑
超时或异常: java.util.concurrent.TimeoutException
```

---

# **方法二：自己封装超时保护**
**比如你需要复杂一点的：**

+ **超时返回兜底数据（比如返回默认值）**

**1. 首先，封装工具类：**

```plain

import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import org.springframework.stereotype.Component;

import javax.annotation.Resource;
import java.util.concurrent.*;

@Slf4j
@Component
public class AsyncHelper {

 @Resource(name = "taskExecutor") // 注入你的自定义线程池
 private ThreadPoolTaskExecutor taskExecutor;

 /**
 * 执行异步任务（带超时保护）
 *
 * @param supplier 任务逻辑
 * @param timeout 超时时间
 * @param unit 时间单位
 * @param <T> 返回类型
 * @return CompletableFuture
 */
 public <T> CompletableFuture<T> runAsync(SupplierWithException<T> supplier, long timeout, TimeUnit unit) {
 CompletableFuture<T> future = CompletableFuture.supplyAsync(() -> {
 try {
 return supplier.get();
 } catch (Exception e) {
 throw new CompletionException(e);
 }
 }, taskExecutor);

 return future.orTimeout(timeout, unit)
 .exceptionally(ex -> {
 log.error("异步任务执行异常或超时：", ex);
 return null; // 这里可以设置默认返回值
 });
 }

 @FunctionalInterface
 public interface SupplierWithException<T> {
 T get() throws Exception;
 }
}
```

```plain
import java.util.concurrent.atomic.LongAdder;

public class AsyncTaskMonitor {

 private static final ConcurrentHashMap<String, TaskStat> monitorMap = new ConcurrentHashMap<>();

 public static <T> Supplier<T> monitor(String taskName, Supplier<T> supplier) {
 return () -> {

 success(taskName, System.currentTimeMillis() - start);
 return result;
 } catch (Exception e) {

 }

 }

 stat.totalTime.add(time);
 }

 stat.failCount.increment();
 stat.totalTime.add(time);

 System.out.println("【监控】任务：" + taskName +
 "，成功次数：" + stat.successCount.sum() +
 "，失败次数：" + stat.failCount.sum() +
 "，平均耗时：" + (stat.totalTime.sum() / (stat.successCount.sum() + stat.failCount.sum())) + " ms");
 });
 }

 LongAdder failCount = new LongAdder();

 }
```

# **2. AsyncHelper 核心代码**
```plain
java


复制编辑
import java.util.concurrent.*;
import java.util.function.Supplier;

public class AsyncHelper {

 private static final ExecutorService executor = Executors.newFixedThreadPool(20);

 public static <T> CompletableFuture<T> runAsync(Supplier<T> supplier,
 long timeout, TimeUnit unit,
 String taskName,
 T defaultValue) {
 String traceId = TraceContext.getTraceId(); // 获取当前TraceId

 Supplier<T> task = () -> {
 long start = System.currentTimeMillis();
 TraceContext.setTraceId(traceId);
 try {
 T result = supplier.get();
 AsyncTaskMonitor.success(taskName, System.currentTimeMillis() - start);
 return result;
 } catch (Exception e) {
 AsyncTaskMonitor.fail(taskName, System.currentTimeMillis() - start);
 System.err.println("【异步异常】任务：" + taskName + "，TraceId：" + traceId + "，异常：" + e.getMessage());
 return defaultValue;
 } finally {
 TraceContext.clear();
 }
 };

 CompletableFuture<T> future = CompletableFuture.supplyAsync(task, executor);

 // 超时保护
 CompletableFuture<T> timeoutFuture = failAfter(timeout, unit, defaultValue);

 return future.applyToEither(timeoutFuture, Function.identity());
 }

 private static <T> CompletableFuture<T> failAfter(long timeout, TimeUnit unit, T defaultValue) {
 CompletableFuture<T> promise = new CompletableFuture<>();
 executor.schedule(() -> promise.complete(defaultValue), timeout, unit);
 return promise;
 }
}
```

# **2. 定义 AsyncResult 类**
```plain
java


复制编辑
public class AsyncResult<T> {

 private boolean success;
 private boolean timeout;
 private T result;
 private Throwable exception;

 public AsyncResult(boolean success, boolean timeout, T result, Throwable exception) {
 this.success = success;
 this.timeout = timeout;
 this.result = result;
 this.exception = exception;
 }

 public static <T> AsyncResult<T> success(T result) {
 return new AsyncResult<>(true, false, result, null);
 }

 public static <T> AsyncResult<T> timeout() {
 return new AsyncResult<>(false, true, null, null);
 }

 public static <T> AsyncResult<T> fail(Throwable e) {
 return new AsyncResult<>(false, false, null, e);
 }

 public boolean isSuccess() {
 return success;
 }

 public boolean isTimeout() {
 return timeout;
 }

 public T getResult() {
 return result;
 }

 public Throwable getException() {
 return exception;
 }
}
```

✅** 成功了，success = true
**✅** 超时了，timeout = true
**✅** 失败了，exception记录异常信息**

```plain
}

}
```

```plain
java


复制编辑
import java.util.*;
import java.util.concurrent.*;
import java.util.function.Supplier;

public class AsyncTasksBuilder {

 private static final ExecutorService executor = Executors.newFixedThreadPool(20);

 private final List<TaskItem<?>> tasks = new ArrayList<>();

 private AsyncTasksBuilder() {}

 public static AsyncTasksBuilder create() {
 return new AsyncTasksBuilder();
 }

 public <T> AsyncTasksBuilder add(String taskName, Supplier<T> supplier, long timeout, TimeUnit unit) {
 tasks.add(new TaskItem<>(taskName, supplier, timeout, unit));
 return this;
 }

 public Map<String, AsyncResult<Object>> invokeAll() {
 Map<String, CompletableFuture<AsyncResult<Object>>> futureMap = new HashMap<>();

 for (TaskItem<?> task : tasks) {
 CompletableFuture<AsyncResult<Object>> future = runTask(task);
 futureMap.put(task.taskName, future);
 }

 CompletableFuture.allOf(futureMap.values().toArray(new CompletableFuture[0])).join();

 Map<String, AsyncResult<Object>> resultMap = new HashMap<>();
 futureMap.forEach((name, future) -> {
 try {
 resultMap.put(name, future.get());
 } catch (Exception e) {
 resultMap.put(name, AsyncResult.fail(e));
 }
 });

 return resultMap;
 }

 private <T> CompletableFuture<AsyncResult<Object>> runTask(TaskItem<T> task) {
 String traceId = TraceContext.getTraceId();
 Supplier<AsyncResult<Object>> wrapped = () -> {
 long start = System.currentTimeMillis();
 TraceContext.setTraceId(traceId);
 try {
 T result = task.supplier.get();
 AsyncTaskMonitor.success(task.taskName, System.currentTimeMillis() - start);
 return AsyncResult.success(result);
 } catch (Exception e) {
 AsyncTaskMonitor.fail(task.taskName, System.currentTimeMillis() - start);
 return AsyncResult.fail(e);
 } finally {
 TraceContext.clear();
 }
 };

 CompletableFuture<AsyncResult<Object>> future = CompletableFuture.supplyAsync(wrapped, executor);
 CompletableFuture<AsyncResult<Object>> timeoutFuture = failAfter(task.timeout, task.unit);

 return future.applyToEither(timeoutFuture, Function.identity());
 }

 private CompletableFuture<AsyncResult<Object>> failAfter(long timeout, TimeUnit unit) {
 CompletableFuture<AsyncResult<Object>> promise = new CompletableFuture<>();
 executor.schedule(() -> promise.complete(AsyncResult.timeout()), timeout, unit);
 return promise;
 }

 static class TaskItem<T> {
 String taskName;
 Supplier<T> supplier;
 long timeout;
 TimeUnit unit;

 TaskItem(String taskName, Supplier<T> supplier, long timeout, TimeUnit unit) {
 this.taskName = taskName;
 this.supplier = supplier;
 this.timeout = timeout;
 this.unit = unit;
 }
 }
}
```

```plain
 public static boolean isOpen(String taskName) {
 BreakerStatus status = breakerMap.get(taskName);
 if (status == null) {
 return false;
 }
 if (status.isOpen()) {
 if (System.currentTimeMillis() - status.openTime > 30_000) {

 if (v.failures >= 5) {
 v.openTime = System.currentTimeMillis();
 }
 return v;
 });
 }

 public static void recordSuccess(String taskName) {
 breakerMap.remove(taskName);
 }

 int failures = 0;
 long openTime = 0;

 }
 }
}
```

```plain
public class AsyncTaskMonitor {

 private static final Map<String, TaskMetrics> taskMetricsMap = new ConcurrentHashMap<>();

 public static void success(String taskName, long costMillis) {
 TaskMetrics metrics = taskMetricsMap.computeIfAbsent(taskName, k -> new TaskMetrics());
 metrics.successCount++;
 metrics.totalCost += costMillis;
 }

 public static void fail(String taskName, long costMillis) {
 TaskMetrics metrics = taskMetricsMap.computeIfAbsent(taskName, k -> new TaskMetrics());
 metrics.failCount++;
 metrics.totalCost += costMillis;

 // 检查是否需要告警
 if (metrics.failCount >= 5 && !metrics.alerted) {
 AlertManager.sendAlert(taskName, metrics.failCount);
 metrics.alerted = true;
 }
 }

 public static long getAvgRespTime(String taskName) {
 TaskMetrics metrics = taskMetricsMap.get(taskName);
 if (metrics == null || (metrics.successCount + metrics.failCount) == 0) {
 return 0;
 }
 return metrics.totalCost / (metrics.successCount + metrics.failCount);
 }

 static class TaskMetrics {
 int successCount = 0;
 int failCount = 0;
 long totalCost = 0;
 boolean alerted = false;
 }
}
```

# **2. 核心组件拆解**
## **2.1 AsyncTaskDispatcher（调度中心）**
```plain
java


复制编辑
public class AsyncTaskDispatcher {

 private static final ExecutorService executor = Executors.newFixedThreadPool(100);

 public static <T> CompletableFuture<AsyncResult<T>> submitTask(String chainId, String taskName, Supplier<T> supplier, long timeoutMs, T fallbackValue) {
 AsyncTrace.start(chainId, taskName);

 CompletableFuture<AsyncResult<T>> future = CompletableFuture.supplyAsync(() -> {
 long start = System.currentTimeMillis();
 try {
 T result = supplier.get();
 AsyncTrace.finish(chainId, taskName, true, null);
 return AsyncResult.success(result);
 } catch (Exception e) {
 AsyncTrace.finish(chainId, taskName, false, e);
 return AsyncResult.fallback(fallbackValue);
 }
 }, executor);

 // 超时处理
 return future.orTimeout(timeoutMs, TimeUnit.MILLISECONDS)
 .exceptionally(ex -> {
 AsyncTrace.finish(chainId, taskName, false, ex);
 return AsyncResult.fallback(fallbackValue);
 });
 }
}
```

**核心能力：**

+ ✅** 提交异步任务**
+ ✅** 自动链路打点**
+ ✅** 超时熔断**
+ ✅** 返回默认值降级**
+ ✅** 统一线程池执行**
