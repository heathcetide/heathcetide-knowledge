宽带语音编解码器

64 kbps比特率，16kHz采样率

iLBC:

专为语音设计的编解码器

13.33ms或20ms帧长度

iSAC:

自适应音频编解码器

支持可变帧长度和比特率

**<font style="color:rgb(0, 0, 0);">AAC</font>**<font style="color:rgb(0, 0, 0);">：高级音频编码，常用于音乐和语音的压缩。</font>


音频文件格式与WebRTC编码的关系

容器格式 vs 编码格式

WAV: 音频容器格式，通常包含未压缩的PCM数据

MP3: 既是压缩格式也是文件格式，使用有损压缩

其他格式: AAC、FLAC、OGG等也结合了容器和编码

与WebRTC的关系

WebRTC处理的是原始编码音频数据，不是文件格式

需要提取和转换文件格式中的数据
WAV文件需要提取PCM数据

MP3文件需要先解码为PCM

然后重新编码为WebRTC支持的编解码器（opus、PCMU等）

处理需求

文件格式需要解码库来提取原始音频

原始音频数据需要重新编码为WebRTC编解码器

必须根据采样率和帧大小计算时序信息


**<font style="color:rgb(0, 0, 0);">编解码</font>**<font style="color:rgb(0, 0, 0);">（Codec）是指编码（编码器，Encoder）和解码（解码器，Decoder）的组合。其主要功能是将数据从一种格式转换为另一种格式。例如，在音频和视频领域，编解码器将声音或视频信号转化为数字信号进行存储、传输，或者将数字信号转化为可播放的声音或视频。</font>

### <font style="color:rgb(0, 0, 0);">编解码器的作用</font>
+ **<font style="color:rgb(0, 0, 0);">编码器</font>**<font style="color:rgb(0, 0, 0);">（Encoder）将原始的音频、视频信号转换为压缩的数字信号，以便存储或传输。</font>
+ **<font style="color:rgb(0, 0, 0);">解码器</font>**<font style="color:rgb(0, 0, 0);">（Decoder）则是将接收到的压缩数字信号还原为原始的音频或视频信号，以便播放或使用。</font>

### <font style="color:rgb(0, 0, 0);">常见的音频编解码器</font>
1. **<font style="color:rgb(0, 0, 0);">PCM</font>**<font style="color:rgb(0, 0, 0);">（Pulse Code Modulation，脉冲编码调制）：是一种无损音频编码方式，用于数字化音频信号，广泛用于CD音质的音频压缩。</font>
2. **<font style="color:rgb(0, 0, 0);">PCMU</font>**<font style="color:rgb(0, 0, 0);">（G.711 μ-law）：是一种常见的音频编码方式，广泛用于语音通信中，如VoIP（语音通信）技术，使用μ-law压缩算法，主要用于美国和日本。</font>
3. **<font style="color:rgb(0, 0, 0);">PCMA</font>**<font style="color:rgb(0, 0, 0);">（G.711 A-law）：与PCMU类似，但采用A-law压缩算法，主要用于欧洲和其他地区的语音通信。</font>
4. **<font style="color:rgb(0, 0, 0);">G.722</font>**<font style="color:rgb(0, 0, 0);">：一种宽带语音编解码器，支持更高质量的语音传输，常用于会议电话、VoIP应用中。它比G.711有更高的音频质量。</font>
5. **<font style="color:rgb(0, 0, 0);">OPUS</font>**<font style="color:rgb(0, 0, 0);">：一种现代的音频编解码器，支持语音和音乐的高效编码。它适用于低延迟、高质量音频压缩，广泛应用于实时通信、流媒体等领域。</font>

<font style="color:rgb(0, 0, 0);">这些编解码器在不同的应用场景中，基于性能、延迟、音质和带宽要求的不同而各有优势。例如，</font>**<font style="color:rgb(0, 0, 0);">OPUS</font>**<font style="color:rgb(0, 0, 0);">适用于高质量低延迟的实时通信，而</font>**<font style="color:rgb(0, 0, 0);">PCM</font>**<font style="color:rgb(0, 0, 0);">则适用于需要无损质量的场景。</font>

+ **<font style="color:rgb(0, 0, 0);">无损质量</font>**<font style="color:rgb(0, 0, 0);">（Lossless Quality）：</font>
+ **<font style="color:rgb(0, 0, 0);">PCM</font>**<font style="color:rgb(0, 0, 0);">（脉冲编码调制）是一种无损的音频编码方式，意味着它在压缩时不会丢失任何音频信息，传输和恢复的音频质量是完全和原始音频一致的。这通常用在需要高度保真度的场景，比如音频CD、专业音频制作等。</font>
+ <font style="color:rgb(0, 0, 0);">因为没有压缩过程，PCM音频文件通常非常大，占用很多存储空间，同时传输带宽也要求较高。</font>
+ **<font style="color:rgb(0, 0, 0);">高质量低延迟</font>**<font style="color:rgb(0, 0, 0);">：</font>
+ **<font style="color:rgb(0, 0, 0);">OPUS</font>**<font style="color:rgb(0, 0, 0);">是一种有损音频编码方式，但它非常注重在压缩和传输过程中保持高音质，并且能够在低延迟的情况下进行实时音频传输。OPUS设计上采用了一些技术，可以在不同的码率和音频条件下动态调整，以确保语音和音乐的质量。</font>
+ **<font style="color:rgb(0, 0, 0);">OPUS</font>**<font style="color:rgb(0, 0, 0);">的音质虽然不如</font>**<font style="color:rgb(0, 0, 0);">PCM</font>**<font style="color:rgb(0, 0, 0);">那样完全无损，但它对于大多数语音和音乐应用来说，提供了非常高的质量，同时延迟较低（对于实时通信尤为重要），这使它在像VoIP、视频会议、在线游戏等需要低延迟和高质量的场合中非常受欢迎。</font>
+ **<font style="color:rgb(0, 0, 0);">PCM</font>**<font style="color:rgb(0, 0, 0);">属于无损编码，音质最高，但不适合带宽受限和低延迟场景。</font>
+ **<font style="color:rgb(0, 0, 0);">OPUS</font>**<font style="color:rgb(0, 0, 0);">属于有损编码，但提供了非常高的音质，并在低延迟和带宽受限的场合表现良好。</font>
