# 一致性
好的！我们将继续沿用**鲁棒性和幂等性工具类的架构设计思路**，为**一致性（Consistency）**提供一个通用、可扩展的工具类框架。

一致性是分布式系统中的核心问题，主要分为以下几种场景：

1. **强一致性**：系统中的所有节点在任意时间点对数据的访问结果都是一致的。
2. **最终一致性**：系统允许不同节点的状态暂时不一致，但最终达到一致。
3. **弱一致性**：不保证最终一致性，通常用于性能优先的场景。

---

## **一致性工具类设计目标**
### **目标1：支持多种一致性场景**
+ **分布式事务**：支持两阶段提交（2PC）、三阶段提交（3PC）或 Saga 模式。
+ **数据同步**：支持最终一致性的数据同步，确保不同节点的状态在一定时间后达到一致。
+ **幂等性保证**：支持在一致性流程中对重复提交的请求进行幂等性处理。

### **目标2：提供统一的接口与扩展**
+ 核心接口支持多种一致性实现（2PC、3PC、Saga、异步补偿）。
+ 支持插件化扩展，便于引入自定义的一致性实现。

### **目标3：支持状态监控与动态配置**
+ 记录一致性处理的状态，便于监控和调试。
+ 支持动态调整一致性策略（例如：从 2PC 切换到 Saga）。

---

## **一致性工具类架构设计**
### 核心模块：
1. **一致性接口**： 定义一致性管理的核心操作，如提交、回滚、状态监控等。
2. **一致性策略实现**：
    - **两阶段提交（2PC）**。
    - **三阶段提交（3PC）**。
    - **Saga 模式**。
    - **异步补偿**。
3. **任务状态管理**：
    - 记录每个任务的执行状态（PENDING、SUCCESS、FAILED）。
    - 提供任务恢复和重试功能。
4. **全局一致性管理器**： 提供统一入口，动态管理不同模块的任务一致性。

### **1. 一致性接口**
```plain
public interface ConsistencyHandler {

    /**
     * 开始一致性任务。
     *
     * @param taskId 唯一任务ID
     * @param action 业务执行逻辑
     * @throws Exception 执行失败时抛出异常
     */
    void begin(String taskId, ConsistencyAction action) throws Exception;

    /**
     * 提交一致性任务。
     *
     * @param taskId 唯一任务ID
     * @throws Exception 提交失败时抛出异常
     */
    void commit(String taskId) throws Exception;

    /**
     * 回滚一致性任务。
     *
     * @param taskId 唯一任务ID
     * @throws Exception 回滚失败时抛出异常
     */
    void rollback(String taskId) throws Exception;

    /**
     * 查询任务状态。
     *
     * @param taskId 唯一任务ID
     * @return 任务状态
     */
    String getStatus(String taskId);
}

/**
 * 定义业务逻辑接口。
 */
@FunctionalInterface
public interface ConsistencyAction {
    void execute() throws Exception;
}
```

### **2. 两阶段提交（2PC）实现**
```plain
java


复制代码
import java.util.concurrent.ConcurrentHashMap;

public class TwoPhaseCommitHandler implements ConsistencyHandler {

    // 记录任务状态
    private final ConcurrentHashMap<String, String> taskStatus = new ConcurrentHashMap<>();

    @Override
    public void begin(String taskId, ConsistencyAction action) throws Exception {
        taskStatus.put(taskId, "PENDING"); // 标记任务为进行中
        try {
            action.execute(); // 执行业务逻辑
            taskStatus.put(taskId, "READY"); // 标记任务准备提交
        } catch (Exception e) {
            taskStatus.put(taskId, "FAILED");
            throw e;
        }
    }

    @Override
    public void commit(String taskId) throws Exception {
        if (!"READY".equals(taskStatus.get(taskId))) {
            throw new IllegalStateException("Task is not ready to commit.");
        }
        taskStatus.put(taskId, "SUCCESS");
    }

    @Override
    public void rollback(String taskId) throws Exception {
        if (!"FAILED".equals(taskStatus.get(taskId))) {
            taskStatus.put(taskId, "ROLLED_BACK");
        }
    }

    @Override
    public String getStatus(String taskId) {
        return taskStatus.getOrDefault(taskId, "UNKNOWN");
    }
}
```

### **3. Saga 模式实现**
Saga 模式通过一系列的独立事务步骤实现一致性，并在失败时执行补偿操作。

```plain
java


复制代码
import java.util.ArrayList;
import java.util.List;

public class SagaHandler implements ConsistencyHandler {

    // 定义步骤
    private static class Step {
        ConsistencyAction action;
        ConsistencyAction compensation;

        Step(ConsistencyAction action, ConsistencyAction compensation) {
            this.action = action;
            this.compensation = compensation;
        }
    }

    private final List<Step> steps = new ArrayList<>();
    private int currentStep = -1; // 当前执行的步骤索引

    @Override
    public void begin(String taskId, ConsistencyAction action) throws Exception {
        throw new UnsupportedOperationException("SagaHandler does not use begin directly.");
    }

    public void addStep(ConsistencyAction action, ConsistencyAction compensation) {
        steps.add(new Step(action, compensation));
    }

    @Override
    public void commit(String taskId) throws Exception {
        for (int i = 0; i < steps.size(); i++) {
            currentStep = i;
            steps.get(i).action.execute(); // 执行当前步骤
        }
    }

    @Override
    public void rollback(String taskId) throws Exception {
        for (int i = currentStep; i >= 0; i--) {
            steps.get(i).compensation.execute(); // 执行补偿操作
        }
    }

    @Override
    public String getStatus(String taskId) {
        return currentStep == steps.size() - 1 ? "COMPLETED" : "IN_PROGRESS";
    }
}
```

#  高可用和容错性  


要实现一个**全面、灵活的高可用（High Availability）和容错性（Fault Tolerance）工具类**，我们将基于以下几个目标来设计，参考一致性、鲁棒性和幂等性的设计模式。

---

## **高可用和容错性工具类设计目标**
### **目标1：核心能力支持**
1. **故障隔离**：
    - 避免单个服务的故障传播到整个系统（例如熔断、隔离策略）。
2. **自动恢复**：
    - 发生故障时提供自动恢复机制（如服务重启、健康检查）。
3. **降级策略**：
    - 服务不可用时提供降级逻辑以确保核心功能可用。

### **目标2：多场景适配**
1. 支持多种容错策略：
    - 重试（Retry）：自动重试失败的请求。
    - 熔断（Circuit Breaker）：隔离不稳定的服务。
    - 限流（Rate Limiting）：限制高并发请求。
    - 降级（Fallback）：在服务不可用时返回默认结果。
2. 动态扩展与组合：
    - 提供可组合的策略（如熔断+限流+降级）。
    - 动态配置调整容错策略的参数（如重试次数、熔断阈值）。

### **目标3：监控与日志**
1. 捕获并记录所有高可用与容错操作的状态和日志。
2. 支持状态监控（如熔断状态、失败次数等），便于调试和维护。

---

## **工具类架构设计**
### **模块化设计**
1. **核心接口**： 定义高可用与容错的基本操作接口。
2. **策略实现**：
    - **重试策略**：自动重试瞬时故障。
    - **熔断策略**：隔离不可用的服务。
    - **限流策略**：保护服务免受高并发流量冲击。
    - **降级策略**：提供服务不可用时的备用方案。
3. **策略组合器**： 支持组合多个策略（如熔断+降级）。
4. **全局管理器**： 动态管理高可用策略，支持按模块注册。
5. **监控与日志**：
    - 捕获操作日志。
    - 记录失败统计、熔断状态等。

## **代码实现**
### **1. 核心接口**
定义核心操作接口，所有高可用和容错策略都需要实现。

```plain
java


复制代码
public interface HighAvailabilityHandler<T> {

    /**
     * 执行带高可用和容错的任务。
     *
     * @param action 需要执行的任务逻辑
     * @return 执行结果
     * @throws Exception 如果任务无法完成，则抛出异常
     */
    T execute(HighAvailabilityAction<T> action) throws Exception;

    /**
     * 设置降级逻辑。
     *
     * @param fallback 降级逻辑
     */
    void setFallback(HighAvailabilityFallback<T> fallback);

    /**
     * 获取当前策略状态（如熔断状态、失败次数等）。
     *
     * @return 策略状态描述
     */
    String getStatus();

    /**
     * 重置策略状态。
     */
    void reset();
}

/**
 * 定义任务逻辑接口。
 */
@FunctionalInterface
public interface HighAvailabilityAction<T> {
    T run() throws Exception;
}

/**
 * 定义降级逻辑接口。
 */
@FunctionalInterface
public interface HighAvailabilityFallback<T> {
    T fallback(Exception e);
}
```

### **2. 重试策略实现**
适用于处理瞬时性故障的场景（如网络波动、超时）。

```plain
java


复制代码
import java.util.concurrent.TimeUnit;

public class RetryHandler<T> implements HighAvailabilityHandler<T> {

    private int maxRetries;          // 最大重试次数
    private long retryIntervalMs;    // 重试间隔时间
    private HighAvailabilityFallback<T> fallback;

    public RetryHandler(int maxRetries, long retryIntervalMs) {
        this.maxRetries = maxRetries;
        this.retryIntervalMs = retryIntervalMs;
    }

    @Override
    public T execute(HighAvailabilityAction<T> action) throws Exception {
        int attempts = 0;
        while (attempts <= maxRetries) {
            try {
                return action.run(); // 尝试执行任务
            } catch (Exception e) {
                attempts++;
                if (attempts > maxRetries) {
                    if (fallback != null) {
                        return fallback.fallback(e); // 执行降级逻辑
                    }
                    throw e; // 超过最大重试次数，抛出异常
                }
                TimeUnit.MILLISECONDS.sleep(retryIntervalMs); // 等待重试
            }
        }
        return null; // 不应该到达这里
    }

    @Override
    public void setFallback(HighAvailabilityFallback<T> fallback) {
        this.fallback = fallback;
    }

    @Override
    public String getStatus() {
        return "RetryHandler: maxRetries=" + maxRetries + ", retryIntervalMs=" + retryIntervalMs;
    }

    @Override
    public void reset() {
        // 重试策略无需重置状态
    }
}
```

### **3. 熔断策略实现**
用于隔离不稳定的服务，防止级联故障。

```plain
java


复制代码
import java.util.concurrent.atomic.AtomicInteger;

public class CircuitBreakerHandler<T> implements HighAvailabilityHandler<T> {

    private int failureThreshold;    // 失败次数阈值
    private long openDurationMs;     // 熔断器打开持续时间
    private AtomicInteger failureCount = new AtomicInteger(0);
    private long openStartTime = 0;
    private HighAvailabilityFallback<T> fallback;

    public CircuitBreakerHandler(int failureThreshold, long openDurationMs) {
        this.failureThreshold = failureThreshold;
        this.openDurationMs = openDurationMs;
    }

    @Override
    public T execute(HighAvailabilityAction<T> action) throws Exception {
        if (isCircuitOpen()) {
            if (fallback != null) {
                return fallback.fallback(new RuntimeException("CircuitBreaker is OPEN"));
            }
            throw new RuntimeException("CircuitBreaker is OPEN");
        }

        try {
            T result = action.run();
            failureCount.set(0); // 重置失败计数
            return result;
        } catch (Exception e) {
            if (failureCount.incrementAndGet() >= failureThreshold) {
                openStartTime = System.currentTimeMillis(); // 打开熔断器
            }
            throw e;
        }
    }

    @Override
    public void setFallback(HighAvailabilityFallback<T> fallback) {
        this.fallback = fallback;
    }

    @Override
    public String getStatus() {
        return "CircuitBreaker: state=" + (isCircuitOpen() ? "OPEN" : "CLOSED") +
               ", failures=" + failureCount.get();
    }

    @Override
    public void reset() {
        failureCount.set(0);
        openStartTime = 0;
    }

    private boolean isCircuitOpen() {
        if (failureCount.get() < failureThreshold) {
            return false;
        }
        return System.currentTimeMillis() - openStartTime < openDurationMs;
    }
}
```

### **4. 限流策略实现**
用于限制高并发请求。

```plain
java


复制代码
import java.util.concurrent.Semaphore;

public class RateLimitingHandler<T> implements HighAvailabilityHandler<T> {

    private final Semaphore semaphore; // 控制并发请求数量
    private HighAvailabilityFallback<T> fallback;

    public RateLimitingHandler(int maxConcurrentRequests) {
        this.semaphore = new Semaphore(maxConcurrentRequests);
    }

    @Override
    public T execute(HighAvailabilityAction<T> action) throws Exception {
        if (!semaphore.tryAcquire()) {
            if (fallback != null) {
                return fallback.fallback(new RuntimeException("Rate limit exceeded"));
            }
            throw new RuntimeException("Rate limit exceeded");
        }

        try {
            return action.run();
        } finally {
            semaphore.release();
        }
    }

    @Override
    public void setFallback(HighAvailabilityFallback<T> fallback) {
        this.fallback = fallback;
    }

    @Override
    public String getStatus() {
        return "RateLimitingHandler: availablePermits=" + semaphore.availablePermits();
    }

    @Override
    public void reset() {
        // 限流策略无需特殊重置
    }
}
```

### **5. 策略组合器**
允许将多种策略组合起来，例如熔断+重试+限流。

```plain
java


复制代码
import java.util.ArrayList;
import java.util.List;

public class CompositeHandler<T> implements HighAvailabilityHandler<T> {

    private final List<HighAvailabilityHandler<T>> handlers = new ArrayList<>();

    public void addHandler(HighAvailabilityHandler<T> handler) {
        handlers.add(handler);
    }

    @Override
    public T execute(HighAvailabilityAction<T> action) throws Exception {
        for (HighAvailabilityHandler<T> handler : handlers) {
            try {
                return handler.execute(action);
            } catch (Exception e) {
                // 当前策略失败时，尝试下一个
            }
        }
        throw new RuntimeException("All strategies failed");
    }

    @Override
    public void setFallback(HighAvailabilityFallback<T> fallback) {
        handlers.forEach(handler -> handler.setFallback(fallback));
    }

    @Override
    public String getStatus() {
        StringBuilder status = new StringBuilder();
        for (HighAvailabilityHandler<T> handler : handlers) {
            status.append(handler.getStatus()).append("\n");
        }
        return status.toString();
    }

    @Override
    public void reset() {
        handlers.forEach(HighAvailabilityHandler::reset);
    }
}
```

## **这四个概念的具体定义**
### **1. 鲁棒性（Robustness）**
+ **定义**：系统在异常或意外情况下仍能保持稳定运行的能力。
    - 即使发生故障、异常输入、资源不足等问题，系统也能处理这些情况，而不会崩溃或产生严重后果。
+ **关键点**：
    - **容错能力**：如错误处理、异常捕获。
    - **降级能力**：当部分功能无法使用时，系统仍能提供基础功能。
    - **健康检查**：主动检测问题并恢复服务。
+ **示例**：
    - 一个支付系统，即使调用第三方支付接口失败，也会记录订单并提供退款机制，而不是直接崩溃。

---

### **2. 幂等性（Idempotency）**
+ **定义**：在分布式系统中，幂等性指的是对同一个操作的重复请求，其结果是相同的，无论这个操作被执行一次还是多次。
    - 幂等性保证了系统不会因为网络重试、重复请求等原因出现意外的多次处理。
+ **关键点**：
    - **重复操作无副作用**。
    - **操作结果不因重复调用而改变**。
+ **示例**：
    - 用户提交支付订单，如果支付接口因网络问题导致请求超时，用户可能重复提交订单，幂等性保证同一个订单只被处理一次。

---

### **3. 一致性（Consistency）**
+ **定义**：一致性是指在分布式系统中，多个节点或组件的数据状态在操作后达到一致的状态。
    - 一致性不是单一的概念，而是包含强一致性、弱一致性、最终一致性等多种形式。
+ **分类**：
    - **强一致性**：所有节点的状态在任何时间点都是一致的。
    - **最终一致性**：系统允许短时间的不一致，但最终会达到一致。
    - **弱一致性**：系统只保证某些约束条件的一致性。
+ **关键点**：
    - 数据同步问题（如分布式数据库的主从复制）。
    - 分布式事务（如 2PC、3PC、Saga 模式）。
+ **示例**：
    - 一个订单服务和库存服务，订单支付成功后，库存减少，这两者的状态必须保持一致。

---

### **4. 高可用性和容错性**
+ **高可用性（High Availability）**：
    - **定义**：系统在大部分时间都能提供正常服务的能力，通常通过设计来减少停机时间。
    - **关键点**：
        * 服务冗余：如主备切换。
        * 自动故障恢复：如健康检查和自动重启。
        * 可扩展性：支持服务扩展以应对高负载。
    - **示例**：
        * 大型电商网站在“黑五”流量激增时，仍然保持无故障运行。
+ **容错性（Fault Tolerance）**：
    - **定义**：系统在部分组件故障时仍能继续提供服务的能力。
    - **关键点**：
        * 局部故障隔离：通过熔断器、隔离策略等，防止故障传播。
        * 服务降级：当某些服务不可用时，提供简化的功能。
    - **示例**：
        * 一个微服务系统中某个服务崩溃时，其他服务仍能继续运行，而不是整个系统崩溃。

---

## **这四个概念的关系**
1. **鲁棒性与容错性**：
    - 容错性是实现鲁棒性的一个子集。
    - 鲁棒性更关注系统在多种异常情况下保持稳定，容错性主要关注硬件或服务故障下的可用性。
2. **幂等性与一致性**：
    - 幂等性是保证一致性的一种手段。例如，在分布式事务中，幂等性可以防止重复操作导致的不一致。
    - 一致性更广泛，幂等性只是一个具体实现。
3. **高可用性与一致性**：
    - 在分布式系统中，高可用性和一致性通常是矛盾的（CAP 理论）。
    - 在需要高可用性时，通常会牺牲强一致性，而选择最终一致性。

---

## **这四个概念之外的系统设计核心概念**
在分布式系统设计中，除了鲁棒性、幂等性、一致性和高可用性/容错性，还需要关注以下几个概念：

### **1. 扩展性（Scalability）**
+ **定义**：系统在负载增加时，能够通过扩展资源（如增加服务器）来保持性能的能力。
+ **关键点**：
    - **水平扩展**（Scale Out）：通过增加更多节点来扩展系统能力。
    - **垂直扩展**（Scale Up）：通过增加单个节点的计算能力。
+ **示例**：
    - 一个高并发电商系统，通过动态添加更多的 Web 服务节点，支撑“双十一”流量高峰。

---

### **2. 可维护性（Maintainability）**
+ **定义**：系统的代码、架构设计是否易于维护、扩展和调试。
+ **关键点**：
    - **模块化设计**：如微服务架构。
    - **日志与监控**：支持实时监控和问题定位。
+ **示例**：
    - 一个日志系统设计支持多维度日志查询，有助于快速排查问题。

---

### **3. 安全性（Security）**
+ **定义**：系统抵御恶意攻击和防止数据泄露的能力。
+ **关键点**：
    - 数据加密、访问控制、身份认证。
    - 防御常见攻击（如 SQL 注入、XSS、CSRF）。
+ **示例**：
    - 支付系统中对用户数据进行加密存储，并使用 OAuth 2.0 认证机制。

---

### **4. 可用性与可靠性（Reliability）**
+ **可用性**：系统在指定时间段内能正常运行的概率。
+ **可靠性**：系统能否保证正确地完成其功能。

---

### **5. 性能优化（Performance Optimization）**
+ **定义**：系统在单位时间内完成更多工作的能力。
+ **关键点**：
    - 数据库优化（如索引、分库分表）。
    - 缓存（如 Redis、Memcached）。
    - 网络优化（如 CDN）。
+ **示例**：
    - 使用 Redis 缓存提高查询性能，降低数据库压力。

---

### **6. 可扩展性（Elasticity）**
+ **定义**：系统能否根据负载动态调整资源分配。
+ **示例**：
    - 云计算平台的弹性扩展能力，根据流量自动添加或释放服务器实例。

---

## **总结**
这四个核心概念（鲁棒性、幂等性、一致性、高可用性与容错性）是系统设计的基础，但并不是唯一的设计目标。在设计复杂系统时，还需要关注其他重要特性，如：

1. **扩展性（Scalability）**
2. **安全性（Security）**
3. **性能优化（Performance Optimization）**
4. **可靠性与可用性（Reliability & Availability）**
5. **可维护性（Maintainability）**
6. **可观测性与监控（Observability & Monitoring）**

每个系统根据需求的不同，可能会优先关注不同的特性，比如电商系统更关注高可用性，金融系统更关注一致性。设计时需要综合这些概念，找到适合具体场景的解决方案。

```plain
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.SecretKeySpec;
import java.util.Base64;

public class AESUtil {

    private static final String ALGORITHM = "AES";
    private static final int KEY_SIZE = 128; // 支持 128、192、256 位

    /**
     * 生成随机 AES 密钥
     */
    public static String generateKey() throws Exception {
        KeyGenerator keyGen = KeyGenerator.getInstance(ALGORITHM);
        keyGen.init(KEY_SIZE);
        SecretKey secretKey = keyGen.generateKey();
        return Base64.getEncoder().encodeToString(secretKey.getEncoded());
    }

    /**
     * AES 加密
     */
    public static String encrypt(String data, String key) throws Exception {
        SecretKeySpec secretKey = new SecretKeySpec(Base64.getDecoder().decode(key), ALGORITHM);
        Cipher cipher = Cipher.getInstance(ALGORITHM);
        cipher.init(Cipher.ENCRYPT_MODE, secretKey);
        byte[] encryptedData = cipher.doFinal(data.getBytes());
        return Base64.getEncoder().encodeToString(encryptedData);

        cipher.init(Cipher.DECRYPT_MODE, secretKey);
        byte[] decryptedData = cipher.doFinal(Base64.getDecoder().decode(encryptedData));
        return new String(decryptedData);
```

### **2. 基于线程池的可扩展性实现**
以本地线程池为例，封装可扩展的工具类。

#### **线程池扩展管理类**
```plain
java


复制代码
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ThreadPoolElasticityManager implements ElasticityManager {

    private final ThreadPoolExecutor threadPool;
    private final int minThreads;
    private final int maxThreads;
    private final AtomicInteger currentLoad = new AtomicInteger(0); // 模拟当前负载
    private final int scaleUpThreshold;  // 扩展阈值（例如任务队列长度达到多少触发扩展）
    private final int scaleDownThreshold; // 缩减阈值（例如任务队列长度减少到多少触发缩减）

    public ThreadPoolElasticityManager(int minThreads, int maxThreads, int scaleUpThreshold, int scaleDownThreshold) {
        this.minThreads = minThreads;
        this.maxThreads = maxThreads;
        this.scaleUpThreshold = scaleUpThreshold;
        this.scaleDownThreshold = scaleDownThreshold;
        this.threadPool = new ThreadPoolExecutor(
                minThreads,
                minThreads,
                60L, TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(),
                Executors.defaultThreadFactory(),
                new ThreadPoolExecutor.AbortPolicy()
        );
    }

    @Override
    public void monitorAndAdjust() {
        int queueSize = threadPool.getQueue().size();
        int currentThreadCount = threadPool.getPoolSize();

        if (queueSize > scaleUpThreshold && currentThreadCount < maxThreads) {
            scaleUp();
        } else if (queueSize < scaleDownThreshold && currentThreadCount > minThreads) {
            scaleDown();
        }
    }

    @Override
    public void scaleUp() {
        int currentThreadCount = threadPool.getPoolSize();
        if (currentThreadCount < maxThreads) {
            int newThreadCount = Math.min(maxThreads, currentThreadCount + 1);
            threadPool.setMaximumPoolSize(newThreadCount);
            threadPool.setCorePoolSize(newThreadCount);
            System.out.println("Scaled up: New thread count = " + newThreadCount);
        }
    }

    @Override
    public void scaleDown() {
        int currentThreadCount = threadPool.getPoolSize();
        if (currentThreadCount > minThreads) {
            int newThreadCount = Math.max(minThreads, currentThreadCount - 1);
            threadPool.setCorePoolSize(newThreadCount);
            threadPool.setMaximumPoolSize(newThreadCount);
            System.out.println("Scaled down: New thread count = " + newThreadCount);
        }
    }

    @Override
    public String getStatus() {
        return "ThreadPool Status - CoreThreads: " + threadPool.getCorePoolSize() +
               ", MaxThreads: " + threadPool.getMaximumPoolSize() +
               ", QueueSize: " + threadPool.getQueue().size();
    }

    public ThreadPoolExecutor getThreadPool() {
        return threadPool;
    }
}
```

```plain
import java.util.concurrent.atomic.AtomicInteger;

public class HorizontalScalabilityManager implements ScalabilityManager {

    private final AtomicInteger currentNodes;  // 当前节点数量
    private final int maxNodes;               // 最大节点数量
    private final int minNodes;               // 最小节点数量
    private final int scaleOutThreshold;      // 扩展阈值（如请求队列长度）
    private final int scaleInThreshold;       // 缩减阈值

    public HorizontalScalabilityManager(int minNodes, int maxNodes, int scaleOutThreshold, int scaleInThreshold) {
        this.currentNodes = new AtomicInteger(minNodes);
        this.minNodes = minNodes;
        this.maxNodes = maxNodes;
        this.scaleOutThreshold = scaleOutThreshold;
        this.scaleInThreshold = scaleInThreshold;
    }

    @Override
    public void scaleOut() {
        int current = currentNodes.get();
        if (current < maxNodes) {
            currentNodes.incrementAndGet();
            System.out.println("Scaled out: Added one node. Current nodes = " + currentNodes.get());
        } else {
            System.out.println("Cannot scale out. Reached max nodes limit.");
        }
    }

    @Override
    public void scaleIn() {
        int current = currentNodes.get();
        if (current > minNodes) {
            currentNodes.decrementAndGet();
            System.out.println("Scaled in: Removed one node. Current nodes = " + currentNodes.get());
        } else {
            System.out.println("Cannot scale in. Reached min nodes limit.");
        }
    }

    @Override
    public void scaleUp() {
        throw new UnsupportedOperationException("Scale up is not supported in HorizontalScalabilityManager.");
    }

    @Override
    public void scaleDown() {
        throw new UnsupportedOperationException("Scale down is not supported in HorizontalScalabilityManager.");
    }

    @Override
    public String getStatus() {
        return "Horizontal Scalability - Current Nodes: " + currentNodes.get();
    }

    /**
     * 模拟负载监控和自动扩展
     */
    public void monitorAndAdjust(int currentLoad) {
        if (currentLoad > scaleOutThreshold) {
            scaleOut();
        } else if (currentLoad < scaleInThreshold) {
            scaleIn();
        }
    }
}
```

提供统一的 CDN 工具类接口，封装上传、刷新和访问的功能。

```plain
java


复制代码
import java.util.Arrays;

public class CDNManager {

    private final CDNProvider cdnProvider;
    private final CacheManager cacheManager;

    public CDNManager(CDNProvider cdnProvider) {
        this.cdnProvider = cdnProvider;
        this.cacheManager = new CacheManager(cdnProvider);
    }

    /**
     * 上传文件并刷新缓存
     *
     * @param filePath 本地文件路径
     * @param targetPath CDN 上的目标路径
     */
    public void uploadAndRefresh(String filePath, String targetPath) {
        try {
            String url = cdnProvider.uploadFile(filePath, targetPath);
            System.out.println("File uploaded to CDN. Access URL: " + url);

            // 刷新缓存
            cacheManager.refreshCache(new String[]{targetPath});
        } catch (Exception e) {
            System.err.println("Failed to upload and refresh CDN: " + e.getMessage());
        }
    }

    /**
     * 获取文件的访问 URL
     *
     * @param targetPath CDN 上的目标路径
     * @return 文件访问 URL
     */
    public String getAccessUrl(String targetPath) {
        return cdnProvider.getAccessUrl(targetPath);
    }

    /**
     * 查询 CDN 状态
     */
    public void getCDNStatus() {
        System.out.println(cdnProvider.getStatus());
    }
}
```
