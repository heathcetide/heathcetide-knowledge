### **幂等性概念**
幂等性（Idempotency）是指一个操作无论被执行多少次，产生的结果都是相同的。幂等性是**分布式系统中非常重要的设计原则**，常用于保证系统在**高并发、网络重试、异常恢复**等场景下的数据一致性。

---

### **幂等性的核心**
+ **执行多次，结果一致**：无论一个操作被执行一次还是多次，其对系统的影响和返回结果都是一样的。
+ **状态无副作用**：重复执行操作不会改变系统的最终状态。

---

### **幂等性示例**
#### **1. 幂等的操作**
+ **HTTP GET**：获取数据，执行多次不会改变数据。
+ **HTTP DELETE**：删除资源，重复删除不会影响结果（资源已经不存在）。
+ **PUT 操作**：更新某个资源为特定值，无论调用多少次，资源的最终状态是确定的。

#### **2. 非幂等的操作（更多的常见于创建 / 对接第三方）**
+ **HTTP POST**：通常用于创建资源，多次执行会创建多个相同的资源。
+ **银行转账操作**：重复转账会导致多次扣款。

### **为什么需要幂等性？**
#### **1. 避免重复执行带来的错误**
在分布式系统中，可能因为以下原因导致某个操作被多次执行：

+ **网络超时或失败导致重试。**
+ **由于异步通信、消息队列重复消费。**
+ **用户误操作（如重复点击提交按钮）。**

#### **2. 确保数据一致性**
+ 在高并发场景下，保证多个线程、请求操作同一资源时数据的正确性。
+ 防止分布式事务未提交完成时的重复请求。

#### **3. 提高系统的鲁棒性**
幂等性降低了系统处理重复请求的复杂性，让系统在发生异常时更容易恢复。

---

### **幂等性实现方式**
幂等性通常需要根据业务场景选择合适的实现方法。以下是常见的实现策略：

---

#### **1. 数据库的唯一约束**
+ **原理**： 利用数据库的唯一约束，确保某些字段值的唯一性，从而实现幂等。
+ **适用场景**： 适用于具有自然幂等性的场景，例如用户注册、订单创建等。
+ **示例**：
    - 用户注册：以用户邮箱为唯一约束。
    - 订单创建：订单号（`orderId`）设置为唯一字段。

```java
CREATE TABLE orders (
    order_id VARCHAR(255) PRIMARY KEY,
user_id INT NOT NULL,
amount DECIMAL(10, 2) NOT NULL
);
```

重复插入相同的 `order_id` 会触发数据库唯一约束错误，从而防止多次创建。

---

#### **2. 唯一请求标识[这个要的是只处理一次请求]**
+ **原理**： 为每个请求生成一个唯一的请求 ID，在处理请求时检查该 ID 是否已经处理过。
+ **适用场景**： 适用于需要手动控制幂等性的操作，如支付请求、扣款等。
+ **实现步骤**：
    1. 客户端生成全局唯一 ID（如 UUID），作为每个请求的唯一标识。
    2. 服务器处理请求时，检查该 ID 是否已经存在。
        * 如果已处理，直接返回结果。
        * 如果未处理，则记录 ID 并执行操作。
+ **代码示例**（基于 Redis 实现请求唯一性）：

```java
public Result handleRequest(String requestId, String data) {
    // 尝试在 Redis 中存储请求 ID，有效期 1 小时
    Boolean isUnique = stringRedisTemplate.opsForValue().setIfAbsent("request:" + requestId, "1", 1, TimeUnit.HOURS);
    if (!isUnique) {
        return new Result("请求已处理", false);
    }

    // 执行业务逻辑
    processData(data);

    return new Result("处理成功", true);
}
```

---

#### **3. 防重复提交[这个是针对用户的操作，限制某个时间只能操作一次，只要是按钮防抖]**
+ **原理**： 针对短时间内的重复提交请求，通过限制用户操作或设置时间窗口来实现幂等。
+ **适用场景**： 适用于用户表单重复提交、按钮防抖等。
+ **实现步骤**：
    1. 给用户操作设置一个标记或时间窗口。
    2. 在标记或窗口内拒绝重复请求。
+ **代码示例**：

```java
@PostMapping("/submit")
public Result submitData(@RequestParam String userId) {
    String key = "submit:lock:" + userId;
    Boolean isLocked = stringRedisTemplate.opsForValue().setIfAbsent(key, "1", 10, TimeUnit.SECONDS);
    if (!isLocked) {
        return new Result("操作过于频繁，请稍后再试", false);
    }

    // 执行业务逻辑
    processSubmission();

    return new Result("提交成功", true);
}
```

#### **4. 幂等性接口设计**
+ **原理**： 对操作本身设计为幂等，例如：
    - **PUT 操作**：更新资源为某个确定状态。
    - **DELETE 操作**：删除资源，资源不存在时返回相同结果。
+ **适用场景**： RESTful 风格接口。
+ **示例**：
    - PUT 操作：

```java

    userService.update(id, user);
    return new Result("更新成功");
}
```

    - DELETE 操作：

```java
@DeleteMapping("/user/{id}")

    return new Result("删除成功");
}
//这段代码中无论是否标记成功失败，总之删除是一定会删
```

+ **适用场景**： 订单支付、交易确认等需要严格状态控制的场景。

## **高阶幂等性设计方法**
### **1. 唯一请求标识 (Request ID)**
通过客户端或系统生成一个全局唯一的请求标识符（如 UUID），在服务端记录已处理的请求，以保证同一个请求不会重复处理。

**实践场景**：

+ 支付系统：同一个支付订单，用户可能会重复点击“支付”按钮，需确保只处理一次。

#### **实现步骤**：
1. 客户端生成 `requestId`，每次请求必须携带。
2. 服务端接收后，检查 `requestId` 是否已处理：
    - 若已处理，直接返回结果。
    - 若未处理，则将其存储并执行业务逻辑。

#### **代码实现：Java + Redis**
```java
import redis.clients.jedis.Jedis;

public class IdempotencyWithRequestId {
    private Jedis redis = new Jedis("localhost");

    public String processRequest(String requestId, String businessLogic) {
        // 检查 Redis 中是否已处理该请求
        if (redis.exists(requestId)) {
            return "Request already processed. Result: " + redis.get(requestId);
        }

        // 执行业务逻辑
        String result = executeBusinessLogic(businessLogic);

        // 记录请求ID到 Redis，并设置过期时间（避免占用过多存储空间）
        redis.setex(requestId, 3600, result); // 设置 1 小时过期

        return result;
    }

    private String executeBusinessLogic(String logic) {
        // 模拟业务逻辑
        return "Processed: " + logic;
    }

    public static void main(String[] args) {
        IdempotencyWithRequestId idempotency = new IdempotencyWithRequestId();

        String requestId = "REQ12345";
        System.out.println(idempotency.processRequest(requestId, "Business A")); // 第一次请求
        System.out.println(idempotency.processRequest(requestId, "Business A")); // 重复请求
    }
}
```

### **2. 数据库唯一约束**
通过数据库的唯一约束来保证幂等性。对于重复的请求，数据库会直接抛出异常（如主键重复），从而避免重复执行。

**实践场景**：

+ 用户注册：同一个邮箱只能注册一次。
+ 订单系统：同一个订单号不能重复生成。

#### **实现步骤**：
1. 在数据库表中添加唯一键约束。
2. 捕获数据库的唯一约束异常，返回正确的响应，而不再执行业务逻辑。

#### **代码实现：Java + MySQL**
```java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;

public class IdempotencyWithDatabase {
    public void processOrder(String orderId, String product) {
        try (Connection conn = DriverManager.getConnection("jdbc:mysql://localhost:3306/test", "user", "password")) {
            String sql = "INSERT INTO orders (order_id, product) VALUES (?, ?)";
            PreparedStatement stmt = conn.prepareStatement(sql);
            stmt.setString(1, orderId);
            stmt.setString(2, product);

            stmt.executeUpdate();
            System.out.println("Order processed successfully: " + orderId);
        } catch (Exception e) {
            if (e.getMessage().contains("Duplicate entry")) {
                System.err.println("Order already processed: " + orderId);
            } else {
                e.printStackTrace();
            }
        }
    }

    public static void main(String[] args) {
        IdempotencyWithDatabase idempotency = new IdempotencyWithDatabase();

        String orderId = "ORDER123";
        idempotency.processOrder(orderId, "Product A"); // 第一次请求
        idempotency.processOrder(orderId, "Product A"); // 重复请求
    }
}
```

### **3. 幂等性令牌 (Idempotency Token)**
服务器返回一个幂等性令牌，客户端在后续请求中携带此令牌，服务器根据此令牌判断请求是否已处理。

**实践场景**：

+ API 请求的幂等性，比如支付或文件上传接口。

#### **实现步骤**：
1. 第一次请求时，生成一个幂等性令牌并返回。
2. 客户端后续请求携带令牌，服务端根据令牌查验是否已处理。
3. 如果已处理，则返回之前的结果；如果未处理，则继续业务逻辑并记录结果。

#### **代码实现：Java + Redis**
```java
import redis.clients.jedis.Jedis;
import java.util.UUID;

public class IdempotencyToken {
    private Jedis redis = new Jedis("localhost");

    // 生成幂等性令牌
    public String generateToken() {
        return UUID.randomUUID().toString();
    }

    // 处理请求
    public String processRequest(String token, String businessLogic) {
        // 检查 Redis 是否存在令牌
        if (redis.exists(token)) {
            return "Request already processed. Result: " + redis.get(token);
        }

        // 执行业务逻辑
        String result = executeBusinessLogic(businessLogic);

        // 存储令牌和处理结果到 Redis
        redis.setex(token, 3600, result);

        return result;
    }

    private String executeBusinessLogic(String logic) {
        // 模拟业务逻辑
        return "Processed: " + logic;
    }

    public static void main(String[] args) {
        IdempotencyToken idempotency = new IdempotencyToken();

        // 第一次请求时生成令牌
        String token = idempotency.generateToken();
        System.out.println("Generated Token: " + token);

        // 使用令牌处理请求
        System.out.println(idempotency.processRequest(token, "Business A")); // 第一次处理
        System.out.println(idempotency.processRequest(token, "Business A")); // 重复处理
    }
}
```

### **4. 幂等性日志 (Idempotency Log)**
记录每次请求的操作日志，幂等性通过检查日志实现。

**实践场景**：

+ 长事务或跨服务操作，通过记录事务日志保证幂等性。

#### **实现步骤**：
1. 为每个请求生成事务日志，记录执行状态（`PENDING`、`SUCCESS`）。
2. 重试时检查日志状态，若已完成则跳过。

#### **代码实现：基于事务日志**
```java
import java.util.HashMap;
import java.util.Map;

public class IdempotencyLog {
    private static Map<String, String> transactionLog = new HashMap<>();

    public String processRequest(String requestId, String businessLogic) {
        // 检查日志状态
        if ("SUCCESS".equals(transactionLog.get(requestId))) {
            return "Request already processed. Result: " + transactionLog.get(requestId);
        }

        // 写入日志，标记为 PENDING
        transactionLog.put(requestId, "PENDING");

        // 执行业务逻辑
        String result = executeBusinessLogic(businessLogic);

        // 更新日志为 SUCCESS
        transactionLog.put(requestId, result);

        return result;
    }

    private String executeBusinessLogic(String logic) {
        // 模拟业务逻辑
        return "Processed: " + logic;
    }

    public static void main(String[] args) {
        IdempotencyLog idempotency = new IdempotencyLog();

        String requestId = "REQ123";
        System.out.println(idempotency.processRequest(requestId, "Business A")); // 第一次请求
        System.out.println(idempotency.processRequest(requestId, "Business A")); // 重复请求
    }
}
```

2. **数据存储与过期管理**：
    - Redis 的 `EX` 过期时间可避免存储空间浪费。
    - 确保幂等数据与主业务数据同步清理。
3. **重试机制与幂等性结合**：
    - 设计支持多次重试的机制，幂等性是重试机制的前提。

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.stereotype.Component;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.TimeUnit;

@Component
public class IdempotencyUtil {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    // 内存级幂等记录（适合单实例场景）
    private static final Map<String, Boolean> localCache = new ConcurrentHashMap<>();

    /**
     * 校验幂等性：基于 Redis
     * @param key        唯一标识（比如用户ID+操作类型+时间戳）
     * @param expireTime 锁定的过期时间（秒）
     * @return true 如果是第一次请求，否则 false
     */
    public boolean checkWithRedis(String key, long expireTime) {
        Boolean isFirstRequest = redisTemplate.opsForValue().setIfAbsent(key, "LOCKED", expireTime, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(isFirstRequest);
    }

    /**
     * 释放 Redis 中的幂等锁
     * @param key 唯一标识
     */
    public void releaseRedisLock(String key) {
        redisTemplate.delete(key);
    }

    /**
     * 校验幂等性：基于内存
     * @param key 唯一标识
     * @return true 如果是第一次请求，否则 false
     */
    public boolean checkWithMemory(String key) {
        return localCache.putIfAbsent(key, true) == null;
    }

    /**
     * 清除内存中幂等状态
     * @param key 唯一标识
     */
    public void clearMemoryLock(String key) {
        localCache.remove(key);
    }

    /**
     * 校验幂等性：基于数据库（假设通过日志表实现）
     * @param idempotencyChecker 幂等性检查器，调用者实现具体的检查逻辑
     * @return true 如果是第一次请求，否则 false
     */
    public boolean checkWithDatabase(IdempotencyChecker idempotencyChecker) {
        return idempotencyChecker.check();
    }

    /**
     * 幂等性检查器接口，用于支持数据库或自定义幂等校验逻辑
     */
    @FunctionalInterface
    public interface IdempotencyChecker {
        boolean check();
    }
}
```

### **3. 幂等性策略：Redis 实现**
适合分布式环境，使用 Redis 的原子操作保证并发安全。

```java
import org.springframework.data.redis.core.RedisTemplate;

import java.util.concurrent.TimeUnit;

public class RedisIdempotencyHandler implements IdempotencyHandler {

    private final RedisTemplate<String, String> redisTemplate;

    public RedisIdempotencyHandler(RedisTemplate<String, String> redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    @Override
    public boolean check(String key, long expireTime) {
        Boolean isFirstRequest = redisTemplate.opsForValue().setIfAbsent(key, "LOCKED", expireTime, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(isFirstRequest);
    }

    @Override
    public void markAsProcessed(String key, String result) {
        redisTemplate.opsForValue().set(key, result, 3600, TimeUnit.SECONDS);
    }

    @Override
    public String getProcessedResult(String key) {
        return redisTemplate.opsForValue().get(key);
    }

    @Override
    public void release(String key) {
        redisTemplate.delete(key);
    }
}
```

### **5. 幂等性管理器**
动态选择策略，支持多种场景下的幂等性。

```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class IdempotencyManager {

    private final IdempotencyHandler handler;

    @Autowired
    public IdempotencyManager(RedisTemplate<String, String> redisTemplate, IdempotencyLogMapper idempotencyLogMapper) {
        String mode = System.getProperty("idempotency.mode", "redis"); // 从配置文件读取
        switch (mode) {
            case "memory":
                this.handler = new InMemoryIdempotencyHandler();
                break;
            case "database":
                this.handler = new DatabaseIdempotencyHandler(idempotencyLogMapper);
                break;
            case "redis":
            default:
                this.handler = new RedisIdempotencyHandler(redisTemplate);
                break;
        }
    }

    public IdempotencyHandler getHandler() {
        return handler;
    }
}
```

### **8. 使用示例**
#### 业务代码
```java
@Autowired
private IdempotencyManager idempotencyManager;

public ApiResponse<String> handleRequest(String userId, String requestId) {
    IdempotencyHandler handler = idempotencyManager.getHandler();
    String key = "IDEMPOTENCY:" + userId + ":" + requestId;

    if (!handler.check(key, 300)) {
        String result = handler.getProcessedResult(key);
        if (result != null) {
            return ApiResponse.success(result); // 返回之前的结果
        }
        throw new DuplicateRequestException("请求已处理，请勿重复提交");
    }

    try {
        String result = "Processed Successfully";
        handler.markAsProcessed(key, result);
        return ApiResponse.success(result);

    } catch (Exception e) {
        throw new RuntimeException("业务处理失败", e);
    } finally {
        handler.release(key);
    }
}
```
