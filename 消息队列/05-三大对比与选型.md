# 05 · 三大对比与选型

## 面试题

### Q1. RabbitMQ / Kafka / RocketMQ 怎么对比？适用场景？

| 维度 | RabbitMQ | Kafka | RocketMQ |
| --- | --- | --- | --- |
| 模型 | AMQP 路由极强 | 日志流 / 分区 | 业务 Topic/Queue |
| 吞吐 | 中 | **极高** | 高 |
| 延迟 | 较低 | 低（批会换吞吐） | 低 |
| 路由 | Exchange 灵活 | 弱（靠 Topic） | Tag/SQL 较好 |
| 堆积 | 一般，过重需小心 | **强** | **强** |
| 事务/可靠 | Confirm + 持久 + Quorum | acks/ISR/EOS | 半消息事务 |
| 延迟消息 | TTL+DLX/插件 | 需外挂 | **原生友好** |
| 运维 | 较熟 | 大数据栈 | Java 栈友好 |
| 典型场景 | 业务解耦、复杂路由、任务 | 日志采集、流计算、事件总线 | 订单交易、电商、互联网业务消息 |

**选型口述：**

- 日志/埋点/大数据管道 → **Kafka**  
- 传统业务、路由复杂、企业集成 → **RabbitMQ**  
- 国内互联网交易链路、要事务消息/延迟消息 → **RocketMQ**（或云上商业版）  

同一公司也可多条：链路日志 Kafka，订单 RocketMQ。
