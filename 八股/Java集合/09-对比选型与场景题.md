# 09 · 对比选型与场景题

> 考前总复习：对比表要能脱口而出；场景题要能落到具体类 + 原因。

---

## 一、对比速记（加长版）

### 1. ArrayList vs LinkedList vs ArrayDeque

| 需求 | 选择 | 原因 |
| --- | --- | --- |
| 普通列表、随机访问 | **ArrayList** | O(1) get，缓存友好 |
| FIFO 队列 / 栈（单线程） | **ArrayDeque** | 比 LinkedList/Stack 更快 |
| 大量中间插入且基准证明更优 | 才考虑 LinkedList | 实际很少 |

### 2. HashMap vs Hashtable vs ConcurrentHashMap

| 需求 | 选择 |
| --- | --- |
| 单线程字典 | HashMap |
| 多线程字典 | **ConcurrentHashMap** |
| Hashtable | 基本不选 |

### 3. HashMap vs LinkedHashMap vs TreeMap

| 需求 | 选择 |
| --- | --- |
| 最快 KV | HashMap |
| 保插入序 / 简易 LRU | LinkedHashMap |
| 按 key 排序、范围查询 | TreeMap |
| 并发有序 | ConcurrentSkipListMap |

### 4. HashSet vs LinkedHashSet vs TreeSet

同「Map 三兄弟」对应：去重无序 / 去重保序 / 去重排序。

### 5. 同步包装 vs CopyOnWrite vs 并发集合

| 方案 | 适用 |
| --- | --- |
| Collections.synchronizedXxx | 简单同步，竞争低 |
| CopyOnWriteArrayList | 读远多于写 |
| ConcurrentHashMap 等 | 通用高并发 |

### 6. 阻塞队列选型（线程池）

| 场景 | 队列 |
| --- | --- |
| 通用有界生产消费 | ArrayBlockingQueue / 有界 LinkedBlockingQueue |
| 直连交接 | SynchronousQueue |
| 优先级 | PriorityBlockingQueue |
| 延迟 | DelayQueue |
| 自建线程池 | **务必有界 + 拒绝策略** |

## 二、场景题详解

### Q1. 统计文章词频，单线程 / 多线程怎么做？

**单线程：**

```text
Map<String, Integer> map = new HashMap<>();
map.merge(word, 1, Integer::sum);
```

或 `getOrDefault` + `put`。

**多线程：**

```text
ConcurrentHashMap<String, LongAdder> map = new ConcurrentHashMap<>();
map.computeIfAbsent(word, w -> new LongAdder()).increment();
```

不要用 HashMap 无锁并发；粗暴 `synchronized` 整表也可，但不如 CHM + LongAdder。

---

### Q2. 如何实现 LRU 缓存？要点有哪些？

**面试手写思路一（LinkedHashMap）：**

- `accessOrder = true`  
- 重写 `removeEldestEntry`，`size() > capacity` 时返回 true  

**思路二：** HashMap + 双向链表，自己维护头尾（更贴近「手撕」）。

**生产：** Caffeine / Guava Cache，支持过期、最大权重、统计、并发。

要点：容量上限、淘汰策略、线程安全、是否过期、hit rate。

---

### Q3. 高并发计数（接口 QPS、库存预减前的计数）用什么？

| 方案 | 说明 |
| --- | --- |
| AtomicLong | 单变量够用 |
| LongAdder | 高竞争下更优（分散热点） |
| CHM + LongAdder | 多 key 计数 |

避免：`HashMap<String,Integer>` 并发自增。

---

### Q4. 生产者-消费者 / 线程池任务缓冲怎么设计？

1. 选 **有界 BlockingQueue**，防止任务无限堆积 OOM  
2. 队列满：拒绝策略（Abort、CallerRuns、Discard、DiscardOldest 或自定义）  
3. 监控队列深度、拒绝次数  
4. 不要默认 `newCachedThreadPool` / 无界 LinkedBlockingQueue 无脑用到生产核心路径  

---

### Q5. 「去重且保持输入顺序」输出？

`LinkedHashSet`：先 addAll，再遍历。  
或 `stream.distinct()`（顺序依赖流是否有序）。

---

### Q6. 自定义对象放入 HashSet 后「明明一样却去不掉」？

排查：

1. 是否没重写 hashCode/equals  
2. 是否重写不一致  
3. 放入后是否改了参与哈希的字段  
4. TreeSet 是否 compare 与 equals 不一致  

---

### Q7. 需要「始终有序的并发 Map」？

`ConcurrentSkipListMap`：跳表实现，并发安全，key 有序，复杂度 O(log n)。  
不要用「TreeMap + 自己 synchronized」除非竞争极低。

---

### Q8. 遍历中删除 ArrayList 一半元素，怎么最高效且正确？

- `removeIf` 一次扫完（底层会紧凑搬移）  
- 或 Iterator  
- 避免每次 `remove(i)` 导致多次 O(n) 搬移叠成 O(n²)  

---

### Q9. 什么时候用 IdentityHashMap、WeakHashMap？（加分）

- **IdentityHashMap**：用 `==` 比较 key，不用 equals；特殊场景（序列化图、代理）  
- **WeakHashMap**：key 弱引用，适合「可被 GC 回收的缓存」；注意 value 强引用链路、并发不安全  

常规业务缓存仍更常用 CHM 或专业缓存库。
