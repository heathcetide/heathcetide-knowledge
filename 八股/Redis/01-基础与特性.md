# Redis · 01-基础与特性

---
#### 1.什么是Redis？
Redis是一款由C语言开发的开源的NoSQL数据库, 基于Key-Value进行存储
因为其是存储数据在内存中的，所以读写性能较高，常被用于作为分布式缓存，
除此之外还经常被用户作为数据库，缓存，分布式锁，搜索引擎，流引擎，简易消息队列甚至可以用来作为向量数据库(虽然性能不佳)

#### 2.Redis到底是单线程还是多线程
Redis在6.0之前是纯粹的单线程的，在Redis6.0之后引入了多线程来优化部分功能，因为Redis的本身已经很快了，内存处理，单线程无锁机制处理，它的核心问题其实现在更多的是网络IO而非数据操作, 
因此Redis引入了多线程来进行优化网络IO部分，主要是从Socket读取数据和将数据写入Socket部分，核心的数据写入这些依旧还是单线程处理的，所以可以说Redis本身依旧是单线程处理的

#### 3.什么是缓存？为什么使用缓存？使用缓存会带来哪些问题？
缓存是数据缓存区，是临时存储数据的地方，一般读写性能较高
使用缓存主要是因为两个原因 高并发和高性能，如果是Redis的话，还要加上其功能丰富的原因
而引入缓存带来的问题就包括
1. 双写不一致性
2. 缓存穿透击穿雪崩问题
3. 数据丢失问题
4. 数据的并发竞争问题


#### 4.Redis是单线程，但是为什么这么快？
1. Redis是存储数据在内存中的，读写性能较高，相比于MySQL这种读取磁盘数据的要快得多
2. Redis是基于C语言开发的，本身的处理能力也更优一些
3. Redis的数据操作是单线程的没有线程之间的切换和加锁带来的性能损耗
4. Redis的IO多路复用和单线程事件循环这种方式能够高效的处理数据

5. Redis基于RESP协议进行传输足够方便
6. Redis具有多种优化后的数据结构，比如SDS简单动态字符串，O（1）获取长度，Hash小数据量使用ziplist节省内存，大数据量用hashtable保证O(1)查询，Zset使用跳表，插入和查询都是O(logN)

#### 5.能解释一下IO多路复用模型吗？

IO多路复用也就是单个线程同时监听多个Socket的连接，从而避免无效等待，充分利用CPU的资源
因为传统的阻塞IO一个线程只能盯着一个连接，连接多了就要开多线程，线程之间的切换也会增大开销

**IO多路复用的原理**
IO多路复用是让一个线程同时监听多个文件描述符。Linux下常用的是
1. epoll :把要监听的socket注册到epoll实例
2. 调用epoll_wait阻塞等待
3. 有事件就绪时,epoll_wait返回就绪的socket列表
4. 挨个处理这些socket的读写
Redis在Linux下用epoll,
macOS下用kqueue,
Windows 下用select。
底层实现不一样,但思路都是一样的:用事件驱动替代线程轮询。

### 6. Select, Poll, Epoll的区别？
它们都是操作系统中用于1/0多路复用的机制,让一个线程能同时监控多个Socket(文件描述符)的状态。
1. select
	是最早的实现,用固定长度的位图表示文件描述符集。每次调用都要把整个位图从用户态拷贝到内核态,内核线性扫描所有描述符检查状态。支持的文件描述符数量被写死为1024,大规模连接场景下下效率很低。
2. poll
	改进了 select的描述符数量限制,用动态数组来存储文件描述符,理论上可以监控任意数量。但每次调用还是得把整个数组拷贝到内核,内核还是得遍历全全部描述符,大量连接时效率问题依然存在。
3. epoll
	是Linux专门优化的版本,用红黑树管理注册的描述符,用就绪链表存储触发的事件。
	描述符只需要注册一次,后续不用反复拷贝。调用epoll_wait时只返回有事件的描述符,不用遍历所有注册的描述符。支持边缘触发和水平触发两种模式,适合高并发服务器。
小结一下:
- select:位图存储,1024限制,每次全量拷贝,内核线性扫描谐
- poll:动态数组存储,无数量限制,每次全量拷贝,内核线性扫描
- epoll:红黑树+就绪链表,无数量限制,只注册一次,只返回就绪描述符

提问:10万个连接里只有100个活跃,select和epoll的性能差距有多大?

回答:select每次调用都要扫描10万个描述符,复杂度O(10万);epoll只处理100个活跃描述符加入就绪链表的回调,epoll_wait也只遍历这100个,复杂度O(100)。差了1000倍。再加上 select每次要把10万个描述符的状态从用户态拷贝到内核态,epoll只需要注册一次后续不用拷贝,内存拷贝开销悄也差了几个数量级。实测下来10万连接场景epoll比select快10倍以上。

提问:epoll的边缘触发为什么要配合非阻塞I/O?
回答:边缘触发只在状态变化时通知一次,如果这次没把数据读完就没有后续通知了。所以必须用循环把数据读干,直到read返回 EAGAIN。如果用阻塞1/0,读到最后没数据了 readd会阻塞等待,整个线程就卡住了,其他连接的事件也处理不了。非阻塞I/O在没数据时立即返回EAGAIN,循环就可以正常退出去处理其他事件。

提问:epoll有什么缺点或者不适用的场景?
回答:epoll 对短连接场景优势不大。每个连接都要epoll_ctl注册-一次,连接一断又要删除,频繁的红黑树操作反而有开销。如果连接数少活跃度高,select/poll够用了,epoll的优势势体现不出来。另外epoll是Linux专有的,写跨平台代码还得兼容其他系统的机制。还有就是epoll在某些内核版本上有bu1g,比如早期版本的惊群问题,Nginx专门用accept_mutex来规避。

#### 7.Redis这么快，为什么不用来当主数据库？
主要是两个原因
1. Redis可能会导致数据丢失，哪怕用了持久化机制，但是基于内存中存储始终有可能会丢失一部分数据的
2. Redis基于内存存储，而内存的成本是很高的
当然确实有公司就是用Redis当主数据库的

#### 8.为什么用Redis？
1. 高性能，Redis基于内存进行读写操作，比MySQL读取磁盘的方式至少快 1～3 个数量级（本地缓存更快，大概比Redis快1-2个数量级）
2. 高并发：Redis4c8g都足够承受十万级并发，而MySQL最多也就是万级并发处理
3. 功能丰富: Redis提供各种的数据结构，包括String，List，Set，ZSet，Hash这些，可以实现各种功能

#### 9.Redis常用的数据类型有哪些？
基本数据结构: String, List, Set, ZSet, Hash
复杂数据结构: Geo, Bitmap, HyperLogLog, Stream
