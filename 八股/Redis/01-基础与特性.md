# Redis · 01-基础与特性

---
#### 1.什么是Redis？
Redis是一款由C语言开发的开源的NoSQL数据库, 基于Key-Value进行存储
因为其是存储数据在内存中的，所以读写性能较高，常被用于作为分布式缓存，
除此之外还经常被用户作为数据库，缓存，分布式锁，搜索引擎，流引擎，简易消息队列甚至可以用来作为向量数据库(虽然性能不佳)

#### 2.Redis到底是单线程还是多线程
Redis在6.0之前是纯粹的单线程的，在Redis6.0之后引入了多线程来优化部分功能，因为Redis的本身已经很快了，内存处理，单线程无锁机制处理，它的核心问题其实现在更多的是网络IO而非数据操作, 
因此Redis引入了多线程来进行优化网络IO部分，主要是从Socket读取数据和将数据写入Socket部分，核心的数据写入这些依旧还是单线程处理的，所以可以说Redis本身依旧是单线程处理的

#### 3.什么是缓存？为什么使用缓存？使用缓存会带来哪些问题？
缓存是数据缓存区，是临时存储数据的地方，一般读写性能较高
使用缓存主要是因为两个原因 高并发和高性能，如果是Redis的话，还要加上其功能丰富的原因
而引入缓存带来的问题就包括
1. 双写不一致性
2. 缓存穿透击穿雪崩问题
3. 数据丢失问题
4. 数据的并发竞争问题


#### 4.Redis是单线程，但是为什么这么快？
1. Redis是存储数据在内存中的，读写性能较高
2. Redis是基于C语言开发的，本身的处理能力也更优一些
3. Redis的数据操作是单线程的没有线程之间的切换和加锁带来的性能损耗
4. Redis的IO多路复用和单线程事件循环这种方式能够高效的处理数据

5. Redis基于RESP协议进行传输足够方便
6. Redis具有多种优化后的数据结构，比如SDS简单动态字符串，O（1）获取长度，Hash小数据量使用ziplist节省内存，大数据量用hashtable保证O(1)查询，Zset使用跳表，插入和查询都是O(logN)

#### 5.能解释一下IO多路复用模型吗？
IO多路复用也就是单个线程同时监听多个Socket的连接，从而避免无效等待，充分利用CPU的资源
##### IO多路复用的原理
传统的阻塞IO,一个线程只能盯一个连接,连接多了就得开很多多线
程,线程切换开销大。
IO多路复用是让一个线程同时监听多个文件描述符。Linux下常用的是
1. epoll :把要监听的socket注册到epoll实例
2. 调用epoll_wait阻塞等待
3. 有事件就绪时,epoll_wait返回就绪的socket列表
4. 挨个处理这些socket的读写
Redis在Linux下用epoll,macOS下用kqueue,Windows 下用
select。底层实现不一样,但思路都是一样的:用事件驱动替代线程轮
询。
#### 6.Redis这么快，为什么不用来当主数据库？
主要是两个原因
1. Redis可能会导致数据丢失，哪怕用了持久化机制，但是基于内存中存储始终有可能会丢失一部分数据的
2. Redis基于内存存储，而内存的成本是很高的
当然确实有公司就是用Redis当主数据库的

#### 7.为什么用Redis？
1. 高性能，Redis基于内存进行读写操作，比MySQL读取磁盘的方式至少快 1～3 个数量级（本地缓存更快，大概比Redis快1-2个数量级）
2. 高并发：Redis4c8g都足够承受十万级并发，而MySQL最多也就是万级并发处理
3. 功能丰富: Redis提供各种的数据结构，包括String，List，Set，ZSet，Hash这些，可以实现各种功能

#### 8.Redis常用的数据类型有哪些？
基本数据结构: String, List, Set, ZSet, Hash
复杂数据结构: Geo, Bitmap, HyperLogLog, Stream
