# 13 · Godot 4 迁移与 Compatibility

---

## 面试 / 自测题

### Q1. Godot 3 → 4 迁移最大坑？

1. 节点改名与物理 API  
2. Tween 成为场景内建对象写法变  
3. 着色器/渲染后端  
4. 部分插件不兼容，要换 4.x 版  

官方提供升级工具，但**大型项目仍需人工回归**。

---

### Q2. 为什么你们项目坚持 GL Compatibility？

- 2D 横版不需要 Forward+ 重管线  
- Android / 低配 Mac / **Web** 更稳  
- 团队美术与特效按 Compatibility 能力来设计，避免「编辑器好看、真机没有」  

代价：高级后处理、部分 3D/渲染特性受限。

---

### Q3. Compatibility 下写特效的原则？

- 能精灵就精灵  
- shader 保持短小，避免花活语法  
- 禁止依赖未验证的 mid-function 控制流等坑  
- 特效可关（设置项），低端机降级  

---

### Q4. 版本升级策略建议？

| 策略 | 说明 |
| --- | --- |
| 锁小版本发正式版 | 如 4.4.1 发 1.0 |
| 大版本另开分支 | 4.5/4.6 升级单独验证 |
| 导出脚本卡版本 | 防止手滑用新编辑器出包 |

不要「顺手升级编辑器」后直接打生产包。

---

### Q5. C# / GDExtension 迁移？

- C# 依赖 .NET 版本与导出裁剪  
- GDExtension 需按平台编译 `.so/.dll/.wasm`  
- 纯 GDScript 项目导出最省心  

---

## 易错点

- 文档看的是 4.2，工程是 4.4，API 已变。  
- Web 渲染后端单独配置被忘掉（`rendering_method.web`）。  
- 第三方插件标注「Godot 4」但只测过 Forward+。
