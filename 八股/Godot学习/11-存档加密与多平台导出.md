# 11 · 存档加密与多平台导出

---

## 面试 / 自测题

### Q1. 存档应该写在哪？

**`user://`**。导出后 `res://` 只读。

常见：

- `user://MainGame.json` 全局设置  
- `user://MyAr_1.json` 槽位进度  

---

### Q2. 为什么用加密读写？

```gdscript
FileAccess.open_encrypted_with_pass(path, FileAccess.WRITE, key)
```

防傻瓜级改档。注意：

- 密钥写死在客户端 **防不住逆向**，只是提高门槛  
- 换密钥会让旧档失效——要做版本迁移或兼容  

---

### Q3. 多槽位存档怎么设计？

- 每槽独立文件 + 元数据（名字、时间、角色头像）  
- 进游戏设 `Global.cd_path` 指向当前槽  
- 回主菜单清空路径并 `remove_play_data()` 防串档  

---

### Q4. 导出预设要注意什么？

| 平台 | 注意 |
| --- | --- |
| Windows | 导出模板、图标、嵌入 PCK |
| macOS | 签名/公证；未签名需用户右键打开 |
| Android | SDK、keystore、包名、权限 |
| Web | 渲染用 Compatibility；包体大；线程需 COOP/COEP |

**编辑器版本 = 导出模板版本。**

---

### Q5. Web 包为什么特别大、难加载？

- 全量美术进 PCK，贴图已是 VRAM 压缩，**再 gzip 几乎不缩小**  
- `wasm` 可用 brotli/gzip 预压缩显著变小  
- 应用 `./tools/compress_web.sh` + 带 Content-Encoding 的静态服务器  

进一步瘦身只能：**裁资源、关移动端双格式贴图、字体子集、分包下载**。

---

### Q6. 导出脚本能自动化什么？

- 校验 Godot 版本  
- 一键 `windows` / `mac` / `apk` / `h5`  
- 检查模板与 Android SDK  
- Web 预压缩与本地预览服务器  

减少「手点导出点错版本」。

---

## 易错点

- 用新引擎导出旧项目未测就上架。  
- Web 用 `file://` 或普通 `http.server` 跑线程版 WASM。  
- 存档路径混用绝对路径，换设备失效。
