# 05 · 信号、资源与数据流

---

## 面试 / 自测题

### Q1. 信号（signal）解决什么问题？

**发布-订阅**：发射方不需要知道谁在听。

```gdscript
signal died(source: Node)
# ...
died.emit(self)
```

连接：

- 编辑器连线  
- 代码：`died.connect(_on_died)`  
- 匿名：`died.connect(func(): ...)`  

解耦 UI、成就、音效、任务与角色核心逻辑。

---

### Q2. 信号「已经连接」报错怎么处理？

重复 `connect` 同一可调用对象会报错。

写法：

```gdscript
if not died.is_connected(_on_died):
    died.connect(_on_died)
# 或
died.connect(_on_died, CONNECT_ONE_SHOT)
```

场景切换 / 对象池复用时尤其容易重复连接。

### Q3. Resource 是什么？和 Node 区别？

| | Node | Resource |
| --- | --- | --- |
| 在树里？ | 是 | 否 |
| 典型 | 角色、相机、UI | 纹理、形状、自定义数据 |
| 复用 | 实例多份 | 可共享同一资源引用 |

自定义：

```gdscript
class_name ItemData
extends Resource
@export var id: String
@export var power: int
```

存成 `.tres`，策划可在编辑器改数值。

---

### Q4. 共享 Resource 的危险？

多个敌人引用**同一个** `Resource` 实例时，运行时改属性会「改一份大家一起变」。

需要独立状态时：

```gdscript
var local_data = base_data.duplicate(true)
```

---

### Q5. 数据流推荐架构（口述）？

常见分层：

1. **表现节点**（角色、怪物）读/写自身状态  
2. **Autoload 数据**（背包、进度 `PlayerData`）  
3. **信号 / 调用** 通知 UI 刷新  
4. **存档模块** 序列化 Autoload 数据到 `user://`  

避免：每个 UI 自己改文件；避免怪物直接改存档字典深层字段却不刷新 UI。

---

### Q6. `Callable`、一等函数？

Godot 4 里方法可当 Callable 传递：

```gdscript
func foreach(arr: Array, fn: Callable) -> void:
    for x in arr:
        fn.call(x)
```

信号槽、按钮回调、延迟调用都依赖它。

## 易错点

- 信号参数类型/个数与槽函数不一致 → 导出后更易炸。  
- 在 `_ready` 前 emit，监听方还没 connect。  
- Resource 路径 `load` 失败要用 `ResourceLoader.exists` 兜底。
