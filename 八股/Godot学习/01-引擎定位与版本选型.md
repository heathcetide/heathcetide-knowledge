# 01 · 引擎定位与版本选型

---

## 面试 / 自测题

### Q1. Godot 是什么？适合做什么？

**Godot** 是开源、MIT 许可的游戏引擎，自带编辑器，主打：

- **2D 一等公民**（节点、TileMap、光照、物理都原生）  
- **3D** 可用，但生态与工具链不如 Unity/UE 厚  
- **轻量、免费、无运行时分成**  
- 脚本默认 **GDScript**（也可 C#、GDExtension）

适合：独立游戏、2D 横版/RPG/回合制、原型验证、教学。  
不太适合：超大型 3A、强依赖特定中间件生态的项目（除非自己补齐）。

---

### Q2. Godot 和 Unity、Unreal 怎么对比口述？

| 维度 | Godot | Unity | Unreal |
| --- | --- | --- | --- |
| 许可/费用 | MIT，免费 | 有运行时/席位费用门槛 | 版税/席位 |
| 2D | 强 | 强 | 可用但不主打 |
| 学习曲线 | 相对平缓 | 中等 | 陡 |
| 资源生态 | 相对小 | 最大 | 偏影视级 |
| 源码 | 可改引擎 | 需特定许可 | 可看源码（协议约束） |

选型一句话：**要免费可控 + 2D/中小团队 → Godot；要商店生态 + 招人多 → Unity；要影视级画面管线 → UE。**

---

### Q3. 为什么项目要「锁死」Godot 小版本？

导出模板、编辑器、`.tscn` 格式、渲染后端会随版本变。

**典型坑**：用 4.7 编辑/导出，到玩家机上却按 4.4 思路排查 → `class_name`、信号参数、动画库等一堆运行时错误。

**原则**：

1. `project.godot` / README 写明版本（如 **4.4.1**）  
2. 导出脚本校验 `--version` 必须是 `4.4.*`  
3. 导出模板目录与编辑器版本一致（如 `export_templates/4.4.1.stable/`）

---

### Q4. Forward+、Mobile、Compatibility 渲染后端是什么？

Godot 4 三种（名字随版本文案略有出入）：

| 后端 | 特点 | 典型平台 |
| --- | --- | --- |
| Forward+ | 现代、功能全、重 | 桌面高配 |
| Mobile | 折中 | 移动 |
| Compatibility（GLES） | 兼容老设备、特性受限 | 低配、Web、部分 Android |

**Web 上误用 Forward+ 会极卡甚至难启动**。2D 横版 + 要上 Web/低配机，优先 **Compatibility**。

项目设置示例：

```ini
renderer/rendering_method="gl_compatibility"
renderer/rendering_method.web="gl_compatibility"
```

---

### Q5. Godot 4 相对 Godot 3 的核心变化（口述三点）？

1. **渲染与 Vulkan/兼容后端重做**，3 的 GLES2 思路不能照搬  
2. **节点与物理 API 改名**（如 `KinematicBody2D` → `CharacterBody2D`，`move_and_slide` 用法变）  
3. **Tween、YSort、部分 UI/主题** 行为变化；动画库（AnimationLibrary）存储方式也变  

迁移要靠官方「从 3.x 升级」文档逐步改，不能只改版本号。

---

## 易错点

- 「能打开工程」≠「导出包能跑」——版本必须一致。  
- Compatibility 下部分 Shader 特性、后处理不可用；写 shader 前先确认后端。
