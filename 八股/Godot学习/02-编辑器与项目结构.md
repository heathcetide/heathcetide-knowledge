# 02 · 编辑器与项目结构

---

## 面试 / 自测题

### Q1. 一个 Godot 项目磁盘上主要有什么？

| 路径 | 作用 |
| --- | --- |
| `project.godot` | 工程配置：主场景、显示、输入、Autoload、渲染 |
| `*.tscn` | 场景（文本可读，可 diff） |
| `*.gd` | GDScript |
| `*.tres` / `.res` | 资源（材质、主题、自定义 Resource） |
| `*.import` | 导入设置旁路文件（导入结果在缓存目录） |
| `.godot/` 或自定义缓存目录 | 导入缓存、编辑器状态（通常不入库或按团队约定） |
| `export_presets.cfg` | 导出预设 |
| `addons/` | 编辑器插件 |

约定好「脚本 / 场景 / 美术」三分目录，长期可维护性远好于全堆根目录。

---

### Q2. Autoload（自动加载）是什么？什么时候用？

在 `project.godot` 里注册的**全局单例节点**，游戏启动即进场景树，可用全局名访问（如 `Global`、`PlayerData`）。

适合：

- 跨关卡状态、存档门面、音频管理、对象池、工厂方法  

不适合：

- 把所有玩法塞进一个上帝对象（后期难测、难拆）

口述：**Autoload = 引擎帮你挂好的全局 Node，不是静态类，但仍在场景树里，有 `_ready`/`_process`。**

---

### Q3. `res://` 和 `user://` 区别？

| | `res://` | `user://` |
| --- | --- | --- |
| 含义 | 工程资源 | 用户可写目录 |
| 导出后 | 只读（打进 PCK） | 仍可写 |
| 用途 | 场景、贴图、脚本 | 存档、设置、热更新下载 |

存档、设置必须写 `user://`，不要写 `res://`。

---

### Q4. 场景实例化常用几种方式？

1. 编辑器里把场景拖成子节点（静态）  
2. `preload("res://...tscn")` + `instantiate()`（运行时）  
3. `load()` 延迟加载（首次会卡，可配合加载屏）  
4. 对象池：预实例化隐藏，复用减少卡顿  

大型项目常用「Autoload 工厂 + 对象池」生成子弹、飘字、UI 弹窗。

---

### Q5. 为什么要有 `.import`？能删吗？

导入器根据 `.import` 把 PNG 等转成运行时格式（如 `.ctex`），并生成缓存。

- **源文件 + `.import` 应进版本库**（团队一致）  
- **缓存目录**可重建，不必人人提交巨大缓存  

误删 `.import` 会导致重新导入、设置丢失（压缩、滤镜等）。

---

## 易错点

- 主场景未设 → 运行黑屏或进错场景。  
- Autoload 脚本报错 → 整项目起不来。  
- Windows / mac 路径大小写：`res://` 在导出 Linux/Web 上大小写敏感。
