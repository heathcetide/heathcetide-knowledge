# 01 · 定位、对比与优缺点

---

## 面试题

### Q1. 为什么说 MyBatis 是半自动 ORM？和全自动有何不同？

| | 全自动 ORM（Hibernate/JPA 典型） | 半自动（MyBatis） |
| --- | --- | --- |
| SQL | 多由框架生成 / HQL | **开发者写 SQL**（XML/注解） |
| 映射 | 对象关系强映射，改表常动实体 | SQL ↔ 对象手工映射，灵活 |
| 优化 | 易「不会写 SQL」难调 | SQL 可见、易针对性优化 |
| 学习 | 对象思维、缓存/脏检查复杂 | 贴近 JDBC，SQL 功底要求高 |

**半自动：** 框架帮你做 **参数绑定、结果集映射、连接管理、缓存插件**，但 **SQL 你自己写**。

---

### Q2. JDBC 有哪些不足？MyBatis 如何解决？

| JDBC 痛点 | MyBatis 做法 |
| --- | --- |
| 样板代码多（获取连接、Statement、遍历 ResultSet、关闭） | 封装执行器与会话，Mapper 方法直接返回对象 |
| 参数拼接易 SQL 注入、`?` 难维护 | `#{}` 预编译；动态 SQL 标签 |
| 结果集手动 `getString` 灌对象 | `resultMap` / 自动映射 |
| 重复 SQL、难复用 | `<sql>` + `<include>` |
| 连接与事务琐碎 | 集成连接池、Spring 事务 |

---

### Q3. MyBatis vs Hibernate？vs JPA？

| 维度 | MyBatis | Hibernate / JPA |
| --- | --- | --- |
| 定位 | SQL 映射框架 | 完整 ORM |
| SQL 控制 | 强 | 弱（可原生 SQL，非主路径） |
| 动态 SQL | 一等公民 | Criteria / 拼串较弱体验 |
| 复杂查询/报表 | 更顺手 | 关联一多易 N+1，需熟练 |
| 数据库迁移 | SQL 方言要自己管 | 方言抽象更好 |
| 互联网现状 | 国内非常主流 | 也有，看团队 |

**JPA** 是规范；Hibernate 是实现。对比时常把 JPA/Hibernate 当「全自动一侧」。

---

### Q4. MyBatis 优点？缺点？

**优点：** SQL 可控；学习曲线相对平；动态 SQL 强；与存储过程/复杂报表友好；插件扩展（分页等）。  

**缺点：** CRUD 样板仍多（→ MyBatis-Plus）；写大量 XML；数据库移植差；二级缓存易踩坑；关联映射配置繁琐。

---

### Q5. 什么是 MyBatis-Plus？和 MyBatis 区别？

**MyBatis-Plus（MP）：** 在 MyBatis 上的增强工具包，不改变核心，只增强。

**作用：** 通用 Mapper CRUD、条件构造器、分页插件、代码生成、乐观锁插件、多租户等。

| | MyBatis | MyBatis-Plus |
| --- | --- | --- |
| CRUD | 手写 | 内置 BaseMapper |
| 条件 | XML/注解 | `QueryWrapper`/`LambdaQueryWrapper` |
| 分页 | 自己或 PageHelper | 内置分页插件 |
| 本质 | 底层仍是 MyBatis | 增强，复杂 SQL 仍可写 XML |
