# 07 · 泛型

> 目标：擦除后果、桥接直觉、PECS 能举例，不只背定义。

---

## 面试题

### Q1. 泛型是什么？有什么作用？

在类型上参数化，让类/接口/方法可复用且保持类型安全。

**作用：**

1. **编译期检查**：`List<String>` 不能 add Integer  
2. **少强转**：取出即 String  
3. **表达契约**：`Comparable<T>`、`Class<T>`  

没有泛型时只能 `List` + Object + 强转，运行期才爆 `ClassCastException`。

---

### Q2. 泛型擦除是什么？带来哪些限制？

javac 在编译后擦除类型参数，插入强转与桥接方法。运行期 `List<String>` 与 `List<Integer>` 的原料类型都是 `List`。

**限制与现象：**

| 现象 | 原因 |
| --- | --- |
| 不能 `new T()` / `new T[]` | 运行期不知道 T |
| 不能 `List<int>`，要用 Integer | 类型参数须是引用类型 |
| 不能用 `instanceof List<String>` | 擦除后无法区分 |
| 反射看到原料类型 | 运行期信息有限（有 Signature 属性可取泛型签名，那是元数据） |
| 重载 `void m(List<A>)` 与 `void m(List<B>)` 不行 | 擦除后签名冲突 |

**桥接方法：** 保证重写在擦除后仍能正确多态（面试提到即可）。

```mermaid
flowchart LR
  Src["List&lt;String&gt; list"] --> Erase["擦除为 List"]
  Erase --> Cast["get 时插入 (String) 强转"]
```

### Q3. 上下界？PECS？

- `List<? extends Number>`：**上界**，可看作 Number 的生产者。能安全 `get` 当 Number；除 null 外不能随意 `add`（编译器不知具体子类型）。  
- `List<? super Integer>`：**下界**，可看作 Integer 消费者。可 `add(Integer)`；`get` 只能当 Object。  

**PECS：** Producer Extends, Consumer Super。  
拷贝 API：`src` 用 extends，`dest` 用 super。

```text
void copy(List<? extends Number> src, List<? super Number> dest)
```

### Q4. 泛型方法与类型推断（加分）

```text
public static <T> T id(T t) { return t; }
```

调用时可推断 T。菱形运算符 `new ArrayList<>()` 推断右侧。
