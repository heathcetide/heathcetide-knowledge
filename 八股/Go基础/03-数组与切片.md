# 03 · 数组与切片

---

## 面试题

### Q1. 数组与切片异同？

| | 数组 `array` | 切片 `slice` |
| --- | --- | --- |
| 长度 | 类型一部分：`[3]int` ≠ `[4]int` | 动态长度 |
| 传递 | **值拷贝整段** | 拷贝 **slice 头**（ptr/len/cap），底层数组可共享 |
| 可比较 | 同类型可 `==` | 不能直接 `==`（只能和 nil） |
| 底层 | 连续内存 | 描述底层数组的一段视图 |

```go
type slice struct {
    ptr unsafe.Pointer
    len int
    cap int
}
```

---

### Q2. 为什么传参用切片而不是数组？

数组传参会**整份拷贝**，大数组昂贵且修改不影响调用方。  
切片只拷贝 24 字节左右的头，改元素可影响共享底层数组；要「隔离」用 `copy` 或重新 `make`+copy。

---

### Q3. array 作函数参数是引用还是值传递？

**值传递（拷贝整个数组）。**  
若要改原数组：传指针 `*[N]T`，或改用切片。

---

### Q4. 切片容量如何增长？
在Go语言中，切片的容量是一种动态增长的机制，当切片的长度超过或者达到容量时，Go会自动的拓展其底层数组的容量，一般是由append触发



**面试口径：** 不够就扩容；小 slice 常翻倍，大 slice 增幅变缓；扩容后旧数组可被 GC。

---

### Q5. 切片作函数参数注意事项？

1. 改 `s[i]` → 影响调用方（共享底层）  
2. `append` 可能换新底层 → **不一定**写回调用方；要把新 slice 返回或用指针  
3. 改 `len`/`cap` 只影响函数内副本头  
4. 并发写同一底层数组需同步  

```go
func appendOne(s []int) []int {
    return append(s, 1) // 必须用返回值
}
```

---

### Q6. nil 切片 vs 空切片？

| | nil 切片 | 空切片 `[]T{}` / `make([]T,0)` |
| --- | --- | --- |
| 指针 | nil | 非 nil（通常） |
| len/cap | 0/0 | 0/0 或 0/cap |
| `== nil` | true | false |
| `append`/`len`/`for` | 都可用 | 同 |

多数 API 行为一致；JSON 序列化等场景可能不同（nil → `null`，空 → `[]`）。

---

### Q7. slice 深拷贝 / 浅拷贝？

- **浅拷贝：** `b := a` 或 `b := a[:]` → 共享底层数组  
- **深拷贝元素：** `b := make([]T, len(a)); copy(b, a)` → 元素独立；若元素是指针/含引用，仍可能共享内部  

真正深拷贝嵌套结构需递归或序列化。

---

### Q8. for 里 append 会发生什么？

正常使用：每次可能扩容。注意：

```go
var out []int
for _, v := range src {
    out = append(out, v) // 正确：接住返回值
}
```

循环里 `defer` + append 另见 defer 章。  
`range` 的 `v` 是拷贝；对指针切片要小心「每次 `&v` 相同」老问题（新版本 loopvar 有变化，面试可提）。

---

### Q9. make 创建 slice 的参数含义？

```go
make([]T, len)           // cap == len
make([]T, len, cap)      // 0<=len<=cap
```

`len` 个元素已是零值；`cap` 是底层容量。

---

### Q10. 如何判断数组是否已排序？

遍历一次检查相邻有序：

```go
func isSorted(a []int) bool {
    for i := 1; i < len(a); i++ {
        if a[i] < a[i-1] { return false }
    }
    return true
}
```

或用 `sort.IntsAreSorted`。

---

### Q11. 判断两个字符串切片是否相等？

不能用 `==`（除和 nil）。用：

```go
reflect.DeepEqual(a, b)
// 或
slices.Equal(a, b) // Go 1.21+
```

自己写则比 len 再逐元素比。
