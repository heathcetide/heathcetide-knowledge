# 18 · 测试、竞态与基准

> 面试常问：怎么测并发、什么是 data race、基准测试怎么写才不算自嗨。

---

## 面试题

### Q1. Go 测试怎么组织？表驱动测试是什么？

文件：`xxx_test.go`，函数：`func TestXxx(t *testing.T)`。

**表驱动：** 一组 case 结构体 + `t.Run` 子测试，清晰好扩。

```go
func TestAdd(t *testing.T) {
    cases := []struct {
        name string
        a, b, want int
    }{
        {"ok", 1, 2, 3},
        {"zero", 0, 0, 0},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if got := Add(tc.a, tc.b); got != tc.want {
                t.Fatalf("got %d want %d", got, tc.want)
            }
        })
    }
}
```

命令：`go test ./...`；只跑某个：`go test -run TestAdd`。

---

### Q2. `t.Error` vs `t.Fatal`？`Helper` 呢？

- `Error/Errorf`：记失败，**继续跑**后续断言  
- `Fatal/Fatalf`：记失败并**立刻结束当前测试函数**  
- `t.Helper()`：标记辅助函数，失败行号指到调用方，便于定位  

---

### Q3. 什么是 data race？怎么检测？

**数据竞争：** 多 goroutine 同时访问同一块内存，至少一方写，且无同步。  
属于未定义行为级 bug（Go 会尽量检测）。

```bash
go test -race ./...
go run -race main.go
```

`-race` 有 CPU/内存开销，CI 建议开；本地可对可疑包开。  
修法：锁、channel、atomic、划清所有权。见 [[16-sync包与原子操作]]。

---

### Q4. 竞态探测器能抓到所有并发 bug 吗？

不能。它抓 **data race**，不保证抓到：

- 死锁  
- 逻辑顺序错误（无竞争但结果错）  
- 原子性/业务不变量问题（多字段）  

所以还要：单元测试、压力测试、`go test -count` 防 flaky、code review。

---

### Q5. 基准测试 `Benchmark` 怎么写？注意什么？

```go
func BenchmarkFoo(b *testing.B) {
    b.ReportAllocs()
    for i := 0; i < b.N; i++ {
        Foo()
    }
}
```

```bash
go test -bench=Foo -benchmem ./...
```

注意：

1. 别在循环外做重活却归因到被测函数  
2. 防编译器优化掉无副作用调用（赋值给包级/`b.Sink` 一类手法按版本）  
3. `-count` 多次看稳定性  
4. 先功能正确再谈 ns/op  

---

### Q6. `Example` 测试有什么用？

`func ExampleXxx()`：既是文档又是测试，输出与 `// Output:` 注释比对。  
适合标准库风格的小 API 说明。

---

### Q7. 如何测需要超时/并发的逻辑？

1. `context.WithTimeout` 包被测调用  
2. `t.Deadline()`（Go 1.15+）感知测试超时  
3. 并发测试结束用 `WaitGroup`，并设超时失败  
4. 用 `-race` 跑并发测试  

```go
select {
case <-done:
case <-time.After(time.Second):
    t.Fatal("timeout")
}
```

---

### Q8. 模糊测试（fuzz）了解吗？

Go 1.18+：`func FuzzXxx(f *testing.F)`，引擎喂随机输入挖 panic/断言失败。  
适合解析器、编解码、校验逻辑。口述到「引擎生成输入 + 种子语料」即可。
