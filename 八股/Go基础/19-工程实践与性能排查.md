## 面试题

### Q1. Go Modules 是什么？`go.mod` / `go.sum`？

- **`go.mod`：** 模块路径、Go 版本、依赖要求（require/replace/exclude）  
- **`go.sum`：** 依赖内容哈希，保证拉取一致、防篡改  

常用：

```bash
go mod tidy     # 增删依赖并整理
go list -m all  # 看模块图
```

`replace` 本地替换；发布库注意语义化版本与 `v2+` 路径规则（了解即可）。

### Q2. 如何做 HTTP 中间件？Context 怎么传？

中间件本质：`func(http.Handler) http.Handler` 包装。

```go
func WithTrace(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        ctx := context.WithValue(r.Context(), traceKey{}, "id")
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
```

要点：用 `r.Context()`；客户端取消可中断下游；超时用 `http.TimeoutHandler` 或自建。见 [[15-Context]]。

### Q3. `pprof` 怎么用？能看什么？

导入 `_ "net/http/pprof"` 或 `runtime/pprof`。

常见 profile：

| 类型 | 看什么 |
| --- | --- |
| `cpu` | 热点函数烧 CPU |
| `heap` | 堆分配 / 残留 |
| `goroutine` | 泄漏、堵塞堆栈 |
| `mutex` / `block` | 锁竞争、阻塞 |

```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30
go tool pprof -http=:8081 heap.out
```

口述流程：**先复现 → 打 profile → 看 Top / Flamegraph → 改分配或锁 → 对比**。

### Q4. 线上 goroutine 泄漏如何快速怀疑？

1. `runtime.NumGoroutine()` 持续上涨  
2. goroutine profile 里大量卡在同一行（channel send/recv、Lock）  
3. 对照代码：缺 `ctx.Done()`、缺 `close`、WaitGroup 不匹配  

见 [[11-Goroutine与Channel]]、[[12-Select与并发模式]]。

---

### Q5. 接口性能、反射、JSON 有什么注意？

1. 热点少用反射；json 可用easyjson/代码生成或换更高效库（看场景）  
2. 避免 `interface{}` 狂装箱  
3. `fmt` 热路径贵，日志要级别与采样  
4. 字符串拼接用 Builder（[[08-字符串与拷贝]]）  
5. 切片预分配 cap，减少扩容  

---

### Q6. `init` 里做什么合适？不做什么？

合适：注册驱动、小范围校验。  
不合适：读大配置失败就静默、起大量 goroutine、连远端且无超时——难测、启动顺序黑盒。  
更推荐 `main` / 显式 `New` 注入依赖。

---

### Q7. 如何做优雅退出（graceful shutdown）？

```go
server := &http.Server{Addr: ":8080", Handler: mux}
go server.ListenAndServe()

// 收信号
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
server.Shutdown(ctx) // 等进行中请求结束或超时
```

同时 cancel 业务 root context，停 worker。见 [[15-Context]]。

---

### Q8. `errgroup` / `singleflight` 了解吗？

- **`golang.org/x/sync/errgroup`：** 一组 goroutine，错误返回并可 cancel 其它  
- **`singleflight`：** 相同 key 的并发请求合并成一次，防缓存击穿  

口述场景：批量 RPC、缓存回源合并。

---

### Q9. 交叉编译怎么做？

```bash
GOOS=linux GOARCH=amd64 go build -o app
```

CGO_ENABLED=0 利于静态部署（无 cgo 时）。容器里常用多阶段构建。
