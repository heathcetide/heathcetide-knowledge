# 09 · 结构体、语法与其它

## 面试题

### Q1. struct 是否可以比较？

- 字段均可比较（无 slice/map/func 等）→ struct **可用 `==`**  
- 含不可比较字段 → 不能 `==`，可用 `reflect.DeepEqual`  

可比较 struct 能作 map key。

### Q2. tag 的用处？

结构体字段标签：元数据字符串，反射读取。

```go
type User struct {
    Name string `json:"name" db:"user_name"`
}
```

用途：JSON/XML 序列化、ORM 列名、校验、swagger 等。**语言不解释 tag**，库解释。

### Q3. switch 如何强制执行下一个 case？

Go **默认不 fallthrough**。需要时写：

```go
switch x {
case 1:
    fmt.Println(1)
    fallthrough  // 强制进入下一 case 体（不判断下一条件）
case 2:
    fmt.Println(2)
}
```

`fallthrough` 只能落到下一个 case 正文。

### Q4. make 和 new 区别？

| | `new(T)` | `make(T)` |
| --- | --- | --- |
| 返回 | `*T`，指向零值 | `T` 本身（slice/map/chan） |
| 用途 | 任意类型分配 | **仅** slice、map、channel |
| 初始化 | 仅零值 | 初始化内部结构可用 |

```go
p := new(int)           // *int
s := make([]int, 0, 10) // []int
```

### Q5. Java 和 Go 的区别？（常考）

| 维度 | Java | Go |
| --- | --- | --- |
| 范式 | OOP 为主，类继承 | 组合 + 接口，无类继承 |
| 错误 | 异常 | `error` + 少用 panic |
| 并发 | Thread / JUC | goroutine + channel |
| 泛型 | 成熟已久 | 1.18+ 才有 |
| 运行 | JVM 字节码 | 编译成本地代码，GC |
| 依赖 | 包管理演进长 | module 简洁 |
| 可见性 | public/private… | 大小写跨包 |
| 继承 | extends | 嵌入（embedding） |

口述抓：**简洁、组合优于继承、CSP 并发、显式错误处理**。

### Q7. 结构体嵌入（embedding）是继承吗？

**不是继承，是组合。** 内嵌字段的方法会提升到外层，外层可「像有这些方法」；但无多态父类指针那套。

```go
type Logger struct{}
func (Logger) Log(msg string) {}

type Server struct {
    Logger // 嵌入
}
// Server 自动有 Log 方法
```

冲突：外层同名方法遮蔽；多嵌入带来同名方法 → 调用可能歧义，要显式指定。

### Q8. JSON tag 常见坑？`omitempty` / `-`？

```go
type U struct {
    Name string `json:"name"`
    Age  int    `json:"age,omitempty"`
    Pwd  string `json:"-"`
}
```

- `omitempty`：零值不输出（注意 `false`、`0`、`""` 都会省）  
- `-`：永不序列化/反序列化  
- 字段必须**导出**才能被 `encoding/json` 访问  
- 反序列化目标常用指针 / 注意类型不匹配

### Q9. 值拷贝 struct 时哪些字段「看起来拷了却仍共享」？

struct 赋值是**浅拷贝字段**：

- 基本类型、嵌套 struct 值字段 → 独立  
- 含 `slice`/`map`/`pointer`/`chan`/`func` → **头或指针被拷贝，底层仍共享**  

要隔离：深拷贝或重新 make/copy。见 [[08-字符串与拷贝]]。

---

### Q10. 空结构体 `struct{}` 除了 set 还有什么用？

- 信号 channel：`chan struct{}` 不占载荷  
- 方法接收者仅作命名空间  
- 节省内存的「有没有」标记  

`size = 0`，但地址可能相同（编译器优化），别用地址当唯一身份硬碰硬。

### Q11. Go 可见性规则再强调一下？

- 大写开头：**跨包导出**  
- 小写：包内  
- 无 Java 的 protected；目录 ≈ 包（同目录同 package 名）  
- 测试文件 `xxx_test.go` 可以 `package foo_test` 做黑盒

### Q12. 结构体内存对齐 / 字段顺序为什么影响大小？

字段按类型对齐要求插入 padding，`unsafe.Sizeof` 可能比「字段大小之和」更大。

```go
type A struct { a bool; b int64; c bool } // 可能比把两个 bool 放一起更大
type B struct { a bool; c bool; b int64 } // 常常更省
```

原则：**相同大小字段靠拢、从小到大或按对齐分组**（具体以架构对齐规则为准）。  
热路径大切片存大量 struct 时，对齐浪费会被放大。

### Q13. 包的初始化顺序？循环依赖怎么办？

顺序（简化）：

1. 先初始化依赖包（深度优先）  
2. 包内：常量 → 变量 → `init`（可多个）  
3. 最后 `main.main`  

**导入循环**（A import B、B import A）→ 编译失败。  
解法：抽第三包放公共类型；依赖倒置（接口放使用方）；合并包。  
`init` 里别做重 IO；详见 [[05-函数方法与闭包#Q3]]。
