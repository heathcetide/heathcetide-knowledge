# 03 · 节点与场景树

---

## 面试 / 自测题

### Q1. 什么是节点（Node）和场景树？

Godot 一切皆 **Node**：

- 每个节点有名字、子节点、脚本、可选处理回调  
- 运行时组成一棵 **场景树（SceneTree）**  
- 「场景 `.tscn`」= 预组装好的节点子树，可实例化多次  

心智模型：**游戏 = 一棵不断变的树 + 每帧遍历感兴趣的节点。**

---

### Q2. 常用生命周期回调？

| 回调 | 时机 |
| --- | --- |
| `_enter_tree` | 进入树（父已在树） |
| `_ready` | 自己和子都进树后（子 `_ready` 先于父，Godot 4 仍是子先） |
| `_process(delta)` | 每帧（受暂停影响可配） |
| `_physics_process(delta)` | 固定物理帧 |
| `_exit_tree` | 离开树 |
| `_notification` | 更底层通知 |

**物理相关位移、碰撞**放 `_physics_process`；纯表现可 `_process`。

---

### Q3. `get_node`、`$`、`%`、组（Group）怎么选？

| 方式 | 用途 |
| --- | --- |
| `$Path` / `get_node` | 相对路径取子节点，路径变就炸 |
| `%UniqueName` | 场景内唯一名，重构路径更稳 |
| `get_tree().get_nodes_in_group("enemy")` | 松耦合批量找对象 |
| 信号 | 解耦「发生了什么」与「谁处理」 |
| 导出 `@export` 拖引用 | 编辑器绑好，避免字符串路径 |

优先：**导出引用 / 唯一名 / 信号**；少写易碎长路径。

---

### Q4. `add_child` 和 `owner`、持久化有什么关系？

- `add_child(node)`：进树，开始处理  
- `owner`：影响「保存场景时是否把该节点存进 `.tscn`」  

运行时动态生成的节点通常**不要**乱设 owner，除非你在做场景编辑器类工具。

---

### Q5. 暂停（pause）怎么理解？

`get_tree().paused = true` 时，默认暂停可处理节点。

节点 `process_mode`（Godot 4）：

- `Pausable`：跟随暂停  
- `WhenPaused`：仅暂停时跑（暂停菜单）  
- `Always`：永远跑  
- `Disabled`：不处理  

暂停菜单所在 CanvasLayer 常设为暂停时仍可点。

---

### Q6. 自由节点 vs 实例化场景？

- **单一场景很大**：难协作、难复用  
- **拆成子场景**：角色、UI、子弹、陷阱各自 `.tscn`，父关卡只负责摆放与脚本编排  

原则：**可变的、复用的、可测试的 → 子场景。**

---

## 易错点

- 在 `_ready` 里 `queue_free` 自己要小心时序。  
- `get_parent().get_parent()` 链条一改层级就挂——用信号或 Group。  
- Compatibility / 导出后路径与编辑器不一致时，先查大小写与依赖丢失。
