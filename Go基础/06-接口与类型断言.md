## 面试题

### Q1. Go 的接口是怎么实现的？
在Go中，接口是一种动态类型，允许定义对象的行为，但是不用指定具体的实现
它的本质是一个动态类型和动态值的结合
动态类型：接口持有的具体数据的类型
动态值：接口持有的具体数据的值或者引用

Go采用鸭子类型的设计哲学，不需要显式的声明实现关系，只要一个类型的方法满足了这个接口的所有方法就默认实现了这个接口

接口的底层实现式一个包含了两个字段的iface结构非空接口或者eface结构的空接口
iface: 非空接口的数据结构
```go
// 非空接口
type iface struct {
    tab *itab         // 指向类型信息和方法表
    data unsafe.Pointer // 指向实际的数据
}
```
eface: 空接口的数据结构
```go
// 空接口
type eface struct {
    _type *_type         // 数据类型信息
    data  unsafe.Pointer  // 指向实际的数据
}
```
- **eface = 只存「类型 + 数据」，无方法表**，对应字面量 `interface{}`
- **iface = itab（类型 + 方法集合匹配关系） + 数据指针**，对应带方法的自定义接口

```go
type itab struct {
    inter *interfacetype // 接口类型信息
    _type *_type         // 实现接口的具体类型信息
    hash  uint32         // 类型 hash 值
    _     [4]byte
    fun   [1]uintptr     // 实现接口方法的函数地址
}

```

### Q2. 使用断言时会发生拷贝吗？
会的，断言的时候会发生拷贝
```go
v := i.(T)      // 得到 T 类型的值
p := i.(*T)     // 得到指针
```
- 断言到 **值类型 `T`**：会把接口里存的数据 **按值拷贝** 出一份 `T`（小对象无所谓；大 struct 有成本）  
- 断言到 **`*T`**：拷贝的是指针（8 字节量级），不拷贝所指对象  
- `i.(type)` type switch 同理  
因此大对象常存指针再断言 `*T`。
`comma-ok`：`v, ok := i.(T)` 失败不 panic。
不过这里值得一提的是断言本身不会造成过大的性能损失，一般业务中不用做专门的防止断言的优化什么的，基本只要防止结构体值拷贝就足够了
