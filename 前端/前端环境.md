在 **Vite** 里，你并不“手动去选” `import.meta.env.PROD` 还是 `import.meta.env.DEV`——它们是 **打包模式 (mode)** 决定的内置布尔常量，Vite 在编译阶段直接把它们替换成 `true / false`：

| 运行命令 | `import.meta.env.MODE` | `import.meta.env.PROD` | `import.meta.env.DEV` |
| --- | --- | --- | --- |
| `vite`<br/>（默认 dev 服务器） | `"development"` | `false` | `true` |
| `vite build` | `"production"` | `true` | `false` |
| `vite --mode staging` | `"staging"` | `false` | `false` |
| `vite build --mode staging` | `"staging"` | `false` | `false` |


**要点**：

+ **PROD / DEV** 只跟 “是不是正式构建产物” 有关。
+ 自己制定的其他模式（比如 `staging`、`test`）时，两者都会是 `false`，你改用 `import.meta.env.MODE` 或自定义变量来分支逻辑。

---

## 1. 选择“模式 (mode)” 的方法
1. **CLI 参数**

```plain
# 开 dev 服务器，但走 staging 配置
vite --mode staging

# 打正式包，但以 test 配置编译
vite build --mode test
```

2. **package.json 脚本**

```plain
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "build:staging": "vite build --mode staging"
  }
}
```

3. **跨平台环境变量（可选）**  
Vite 不用 `NODE_ENV` 来区分，但很多库（如 React、Vue）仍会看它。你可以并列写：

```plain
NODE_ENV=production vite build --mode production
```

---

## 2. 给不同模式准备对应 `.env` 文件
Vite 会按 **优先级** 读取：

1. `.env`（所有模式通用）
2. `.env.[mode]`（对应 `vite --mode xxx`）
3. `.env.local`（本地私密，不进 Git）
4. `.env.[mode].local`（某模式的私密）

**规则**：文件里只有前缀 `**VITE_**` 的变量才会暴露到浏览器代码，其他键只在 `vite.config.js` 内可用。

示例：

```plain
# .env.production
VITE_API_BASE_URL=https://api.example.com

# .env.staging
VITE_API_BASE_URL=https://staging-api.example.com
```

---

## 3. 在代码里怎么用
```plain
// 1. 判断当前模式
if (import.meta.env.MODE === 'staging') {
  // 走灰度逻辑
}

// 2. 依赖内置布尔量
if (import.meta.env.PROD) {
  // 覆盖 console，或引入 Sentry
}

// 3. 读取自定义变量
axios.defaults.baseURL = import.meta.env.VITE_API_BASE_URL
```

---

### 小结
+ `import.meta.env.PROD / DEV`**自动根据你用的命令** 决定，不能手动改。
+ 想要更多分类，用 `vite --mode xxx` 并在 `.env.xxx` 里放自定义变量，或在运行时代码里读 `import.meta.env.MODE`。
+ 任何需要暴露到前端的变量名前加 `VITE_`，否则只在 Vite 配置脚本里可见。

这样就能在 **开发 / 预发 / 生产** 等多套环境之间自由切换而无须改动源码。
