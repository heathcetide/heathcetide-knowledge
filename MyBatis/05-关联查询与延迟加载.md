# 05 · 关联查询与延迟加载

---

## 面试题

### Q1. 能否一对一、一对多关联查询？有哪些实现？多表关联怎么做？

**能。** 常见方式：

1. **单条 SQL JOIN + resultMap**  
   - `association`：一对一 / 多对一  
   - `collection`：一对多  
2. **分步查询：** `association/collection` 的 `select` 属性指定另一条语句，用列值当参数再查  
3. **业务层：** 两次 Mapper 调用自己组装（清晰可控）  

**一对一：** 用户↔详情用 `association`。  
**一对多：** 用户↔订单用 `collection`，注意用主键聚合，避免笛卡尔积把一行拆成多 User。

---

### Q2. 是否支持延迟加载？原理？懒加载 vs 立即加载？

**支持**（需配置）：

```xml
<settings>
  <setting name="lazyLoadingEnabled" value="true"/>
  <setting name="aggressiveLazyLoading" value="false"/>
</settings>
```

`association`/`collection` 可 `fetchType="lazy"` / `eager`。

**原理（口述）：**

1. 分步查询场景下，先返回主对象  
2. 对延迟属性创建 **代理**（Javassist/CGLIB）  
3. **第一次访问**该属性时，拦截器触发再执行关联 SQL 装入真实数据  

**懒 vs 立即：**

| | 懒加载 | 立即加载 |
| --- | --- | --- |
| 时机 | 用到再查 | 主查询时一起查出 |
| 优点 | 省无用关联 | 一次拿全，避免事后打库 |
| 风险 | N+1、Session 关闭后访问报错 | 一次 SQL 重或数据过大 |

Spring 下 Session 随请求关，懒加载要保证打开时加载完，或改用 JOIN/业务组装。

---

### Q3. 如何避免 N+1？

N+1：查 1 次列表 + 每行再查关联 = 1+N。  

**解法：**

1. JOIN + `collection`/`association` 一次查出（注意一对多重复行用嵌套结果映射）  
2. 批量：先查主列表，收集 id，`WHERE id IN (...)` 一次查关联，内存分组  
3. 关懒加载误用；或对固定场景强制 eager  
4. 二级缓存慎用「掩盖」N+1，根因仍要改查询
