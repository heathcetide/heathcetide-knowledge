# 04 · 动态 SQL

---

## 面试题

### Q1. 动态 SQL 是做什么的？有哪些标签？执行原理？

**作用：** 按条件拼接 SQL，避免在 Java 里字符串累加，集中维护且可读。

**常用标签：**

| 标签 | 用途 |
| --- | --- |
| `<if>` | 条件成立才拼一段 |
| `<where>` | 包住条件，自动去多余 AND/OR，无条件则不加 WHERE |
| `<set>` | 动态 UPDATE 字段，去掉尾逗号 |
| `<choose><when><otherwise>` | 类似 switch |
| `<foreach>` | IN 集合、批量 insert 多 values |
| `<trim>` | 自定义前后缀与覆盖前缀 |
| `<bind>` | 绑定 OGNL 派生变量（如模糊查询拼接 %） |

**解析与执行：**

1. 启动解析 XML，动态节点变成 `SqlNode` 树（`IfSqlNode`、`ForEachSqlNode`…）  
2. 运行时传入参数对象，OGNL 计算条件  
3. `DynamicSqlSource`/`RawSqlSource` 生成最终 SQL + 参数映射  
4. 再走预编译（`#{}`）执行  

每次调用会按参数 **重新构建 SQL 文本**（结构可变），但不是解释执行脚本语言，开销通常可接受。

---

### Q2. 动态 SQL 执行效率受影响吗？如何优化？

- 有一定 OGNL 与字符串构建成本，相对网络与 DB 执行通常 **不是主瓶颈**  
- 优化：避免过度复杂嵌套；稳定高频 SQL 可拆成多条静态语句；`foreach` 注意 IN 列表长度；批量控制批大小  
- 真正慢多在 **SQL 本身与索引**，用日志看最终 SQL + EXPLAIN  

---

### Q3. 动态表名和列名如何实现？

必须用 `${}` 拼接，例如 `ORDER BY ${orderColumn}`、`FROM ${tableName}`。  

**安全：** 白名单校验（只允许已知列名/表名），禁止用户原始字符串直接进 `${}`。
