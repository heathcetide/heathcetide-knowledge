# 03 · 参数映射与结果封装

---

## 面试题

### Q1. `#{}` 和 `${}` 的区别？

| | `#{}` | `${}` |
| --- | --- | --- |
| 方式 | 预编译占位 `?` | **字符串替换**进 SQL |
| 注入 | 安全 | **有注入风险** |
| 场景 | 参数值 | 动态 **表名/列名/order by 列**（必须白名单校验） |
| 类型处理 | TypeHandler | 直接拼文本 |

口诀：**能用 `#` 绝不用 `$`；用 `$` 必须校验。**

---

### Q2. XML 映射文件里除了 select/insert/update/delete 还有什么？

常见：`<resultMap>`、`<sql>`、`<include>`、`<cache>` / `<cache-ref>`、动态标签（`if/where/set/foreach/choose…`）、`<selectKey>`、`<insert useGeneratedKeys>`、关联 `association`/`collection` 等。

---

### Q3. resultMap 和 resultType 区别？sql 标签作用？include 同 id？

- **resultType：** 指定返回类型（别名或全名），列名≈属性名（或开驼峰）自动映射  
- **resultMap：** 细粒度映射：列别名、关联、鉴别器、懒加载等；复杂对象用它  

**`<sql id="cols">`：** 可复用 SQL 片段。  
**`<include refid="cols"/>`：** 引用片段。  

**不同 XML 的 id：** `namespace + id` 全局唯一；**不同 namespace 可以有相同 id**。  
若 A 的 `<include refid="xx"/>` 引用 B 的 sql：用 **namespace.id** 全限定 refid，或同文件内短 id。

---

### Q4. XML 映射文件和 Mapper 接口的关系？

一对一约定：namespace = 接口 FQCN；方法 ↔ 语句 id。  
可以只有 XML 用 `SqlSession.selectList("ns.id")` 调用（老风格）；现代主流接口绑定。

---

### Q5. 如何将 SQL 结果封装为目标对象返回？

1. `ResultSetHandler` 遍历 ResultSet  
2. 按 `resultType` 反射建对象，或按 `resultMap` 映射列→属性  
3. TypeHandler 做 JDBC Type ↔ Java Type  
4. 关联映射则触发 `association`/`collection`（立即或延迟）  
5. 多行可聚合成 List；主键相同时 collection 嵌套组装  

---

### Q6. 是否可以映射 Enum？

可以。默认 `EnumTypeHandler`（存 name）或 `EnumOrdinalTypeHandler`（存下标）；也可自定义 TypeHandler 存 code。

---

### Q7. 为什么推荐别名机制？

`typeAliases` 把长 FQCN 收成短名（如 `User`），XML 更短、少写错；包扫描可批量注册。复杂项目仍可用全名避免冲突。

---

### Q8. 如何处理复杂对象嵌套映射？

`resultMap` + `association`（一对一）+ `collection`（一对多）；或分步查询 + 延迟加载。见 [[05-关联查询与延迟加载]]。
